# SpaceMaid 发布部署指南

## 一、构建要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 1809 及以上 / Windows 11，x64 |
| SDK | .NET 8 SDK（8.0.x） |
| 仓库位置 | `SpaceMaid/Code/`（解决方案 + 源码 + 测试） |
| 权限 | 发布机器需要能写 `bin/Release/`；不影响目标机的安装方式（本工具免安装） |

```bash
cd SpaceMaid/Code
dotnet restore space-maid.slnx
```

## 二、开发构建与测试

```bash
dotnet build space-maid.slnx              # Debug 构建，目标 0 警告 0 错误
dotnet test space-maid.slnx               # 全量用例（内核 + 界面）
dotnet test tests/SpaceMaid.Core.Tests/SpaceMaid.Core.Tests.csproj   # 只跑内核
```

用例数与逐条验收对照见 [测试报告.md](测试报告.md)。

> 注意：如果 `SpaceMaid.App` 或 `SpaceMaid.App.Tests` 正在被改动，先看 `git status`，避免构建到一半的代码进入发布包。

## 三、Release 单文件自包含发布

发布参数**已固化在 `Code/src/SpaceMaid.App/SpaceMaid.App.csproj`** 中，且**仅在 `Release` 配置生效**（`Condition="'$(Configuration)' == 'Release'"`，或本身就是仅在 Release 下才有意义的属性）：

| 属性 | 值 | 作用 |
| --- | --- | --- |
| `RuntimeIdentifier` | `win-x64` | 固定 64 位 Windows 目标 |
| `SelfContained` | `true` | 自带 .NET 8 运行时，目标机免安装 |
| `PublishSingleFile` | `true` | 打成单个 exe |
| `IncludeNativeLibrariesForSelfExtract` | `true` | 原生库也一起进单文件自解压 |
| `EnableCompressionInSingleFile` | `true` | 单文件内部压缩，体积约减半 |
| `DebugType` | `none` | 不产出 pdb |
| `SatelliteResourceLanguages` | `zh-Hans;en` | 精简本地化资源，减小体积 |
| `ApplicationManifest` | `app.manifest` | 固定管理员权限清单（见第五节） |
| `AssemblyName` | `SpaceMaid` | 产物 exe 名为 `SpaceMaid.exe`（工程目录名是 `SpaceMaid.App`） |

发布命令：

```bash
dotnet publish Code/src/SpaceMaid.App -c Release
```

### 产物路径与命名

```
Code/src/SpaceMaid.App/bin/Release/net8.0-windows/win-x64/publish/SpaceMaid.exe
```

- 文件名固定为 **`SpaceMaid.exe`**（由 `AssemblyName` 决定，**不叫** `SpaceMaid.App.exe`）；
- 单个 exe 即为完整可运行程序，**不需要**其他 dll、不需要目标机安装 .NET 运行时；
- 产物为自包含单文件，体积在几十 MB 量级（压缩已开启）；
- `publish/` 目录下不应出现 `SpaceMaid.Core.dll`、`HandyControl.dll` 等独立文件（若出现，说明单文件参数没有生效，检查 `-c Release` 是否漏写）。

## 四、运行与部署

1. 把 `SpaceMaid.exe` 复制到目标机任意目录（例如 `D:\Tools\SpaceMaid\`），双击运行；
2. 首次运行按第七节的位置自动创建设置、日志与隔离区目录；
3. **每次启动都会弹一次 UAC**（见第五节），这是设计行为而不是故障。

### 建议

- **把隔离区放到非系统盘**（例如 `D:\SpaceMaidQuarantine`）。隔离区与源文件同卷时，清理只是换个目录，**C 盘空间不会立刻下降**，要等保留期结束或手动清空隔离区后才真正释放；
- 不要在可移动介质上放隔离区（U 盘拔掉后无法还原，程序会给出警告）。

## 五、管理员清单说明（UAC 提示）

`Code/src/SpaceMaid.App/app.manifest` 固定声明：

```xml
<requestedExecutionLevel level="requireAdministrator" uiAccess="false" />
```

由此产生的可预期表现：

| 现象 | 说明 |
| --- | --- |
| 双击 exe 立即弹 UAC | 设计如此（需求 3.6 定稿：固定 `requireAdministrator`，不做按需提权）。程序不做任何绕过或"记住授权"处理 |
| 全流程只有一次 UAC | 所有清理项都在同一个管理员会话内完成，**不会出现"清到一半提示需要提权"** |
| 取消 UAC | Windows 直接拒绝启动进程，程序不会以普通权限运行 |
| 被以普通权限拉起 | 程序应拒绝进入清理流程（运行期自检，见"当前状态"） |
| 清单里的其他声明 | Win10/11 兼容性、per-monitor v2 DPI、`longPathAware`（长路径支持） |

**为什么需要管理员权限**：要清理系统临时目录（`C:\Windows\Temp`）、Windows 更新下载缓存、传递优化缓存、系统日志与蓝屏转储等系统位置。程序应在首次启动时用一句话向用户说明这一点，避免用户对 UAC 弹窗产生疑虑（需求 3.6-4）。

## 六、杀软误报的应对

本工具需要管理员权限、且会批量移动文件到隔离区，这类行为特征容易触发杀毒软件的启发式告警。**这些告警通常不是真的检出威胁**，但需要如实向用户说明并给出处理方式。

| 现象 | 应对 |
| --- | --- |
| 单文件 exe 首次运行被拦 | 在杀软中对该 exe **单独**添加排除项（只需排除 `SpaceMaid.exe` 一个文件，不需要排除整个目录） |
| Defender 报"启动项/脚本行为"类告警 | 本工具**不注册开机自启、不创建计划任务、不安装服务、不写注册表**。可据此向用户说明：这些都是可验证的事实（无计划任务、无服务、无自启项） |
| 打包体积大导致首次启动慢 | 自包含单文件首次运行需要自解压，属正常现象；开启了压缩会略增首次启动时间 |
| 企业环境保护 | 若组织禁止运行未签名且需要管理员权限的程序，需走内部白名单流程；本版本**没有代码签名**（见下） |

**关于代码签名**：当前发布流程**不包含数字签名**。因此 Windows SmartScreen 可能提示"未知发布者"。如果后续要做签名，需要在发布前增加签名步骤（本指南不含签名证书的获取与管理）。是否引入签名由发布者决定，**不要在没有证书的情况下伪造签名步骤**。

## 七、日志与数据位置

| 数据 | 路径 | 说明 |
| --- | --- | --- |
| 用户设置 | `%AppData%\SpaceMaid\settings.json` | 隔离区基目录、保留天数（默认 7，范围 1-365）、日志目录、报告目录、回收站范围。**读不到或读坏了回默认值，不打断启动** |
| 日志 | `D:\logs\SpaceMaid\spacemaid-yyyyMMdd.log` | 按日分文件；默认滚动保留 30 天，**在下次启动时惰性清理**（无常驻进程）；目录不可写时回退到 `%LocalAppData%\SpaceMaid\logs\` |
| 清单与复核报告 | `D:\logs\SpaceMaid\清单\<yyyyMMdd-HHmmss>\` | `清单.md` + `清单.csv`（执行前），`复核报告.md`（执行后）；不可写时回退 `%LocalAppData%\SpaceMaid\reports\` |
| 隔离区 | 用户自定义；默认实际存放于 `%LocalAppData%\SpaceMaid\Quarantine` | 组织形式 `<隔离区>\SpaceMaid\Quarantine\<yyyyMMdd-HHmmss-fff>\`，内含 `map.json`（还原唯一依据）与 `payload\`（实体文件） |

> 隔离区路径的两级结构要讲清楚：用户设置里选的是**基目录**（默认 `%LocalAppData%`），实际存放位置是它下面的 `SpaceMaid\Quarantine`，这样不会污染用户自己选的目录结构。

## 八、升级

1. 关闭 SpaceMaid（工具不常驻，关窗即退出）；
2. 用新版本 `SpaceMaid.exe` **直接覆盖**旧文件；
3. 完成。

**升级不会动用户数据**：

- `%AppData%\SpaceMaid\settings.json` 保留；
- `D:\logs\SpaceMaid\` 下的日志、清单与复核报告保留；
- **隔离区与其映射表保留**——旧版本隔离的文件在新版本里仍可还原、仍按原保留期到期释放。

不需要先卸载旧版本再安装新版本（本工具是免安装单文件）。

## 九、卸载

本工具**没有安装程序**，卸载即"删除文件"，但要注意保留与清理的边界：

| 步骤 | 操作 | 说明 |
| --- | --- | --- |
| 1 | 删除 `SpaceMaid.exe` | 程序本体，随你放的位置删除即可 |
| 2 | 按需处理 `%AppData%\SpaceMaid\settings.json` | 删除即回到默认设置；如果以后还打算用，建议保留 |
| 3 | **先处理隔离区，再删除它** | **重要**：如果隔离区里还有未到期的文件，直接删掉隔离区目录等于**放弃这些文件的还原能力**。建议先把还需要的东西还原回原位，或确认不再需要后再删除 |
| 4 | 按需清理 `D:\logs\SpaceMaid\` | 日志、清单与复核报告，纯记录，可自行清理 |
| 5 | 无需其他操作 | **不存在**需要清理的自启项、计划任务、系统服务或注册表键——工具从未创建过它们 |

**保留用户隔离区与设置是本项目的默认立场**：升级与卸载流程都不应主动删除隔离区内容或用户设置。任何"卸载时顺手清空隔离区"的设计都是错的——那会把用户唯一可还原的副本删掉。
