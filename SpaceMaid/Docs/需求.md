## 1 总体概述

### 1.1 产品定位

SpaceMaid 是一个**面向普通 Windows 用户的 C 盘（系统盘）空间清理工具**，只做一件事：把系统盘上"该清的垃圾"安全地清掉，把"可能是垃圾的东西"摆到用户面前让用户自己决定。

产品围绕两条主线设计：

1. **确定是垃圾的，一键清掉，不需要用户操心**——这类对象的共同特征是：由系统或软件自己生成、删掉之后会被自动重建、删除行为被业界长期公认为安全。用户不需要逐条确认，扫描完直接清。
2. **不确定是不是垃圾的，摊开给用户看，勾选后再清**——这类对象是用户自己的数据或可再下载的资源（下载目录里的安装包、各种开发包管理器缓存、聊天软件的文件缓存……）。它们**默认不删**，由用户勾选决定。

**范围边界**：本工具**只处理 C 盘（系统盘）**上的清理项，不扫描也不清理其他分区（回收站默认也只处理 C 盘一个，见 2.5）。

原始需求（用户提出）：清理分"必清理项"与"选择清理项"两档。经评估，在两档之间还存在一层**"删了可能影响功能或数据"**的对象（休眠文件、系统还原点、卸载残留、聊天记录缓存等）——放进"必清"会出事，放进"选择"又容易被用户无脑全勾。因此本需求采用业界通行的**三档制 + 回收站单列**，详见第 2 章（该调整已由用户确认，见 9.1）。

### 1.2 核心约束前置强调

1. **安全第一，宁可少清不可错清**：清理范围严格限定在显式白名单内，白名单之外的路径一律不碰（见 4.2）；
2. **先扫描，后执行**：任何清理动作之前必须先给出体积明细与"本次可处理 X GB"（同卷时如实标注"尚未释放"），禁止无预览的盲清；
3. **L1 免逐项确认，其余必须用户勾选**：L1 扫描后随"一键清理"执行；L2 / L3 / 回收站必须由用户勾选，L3 还需二次确认（注意：L1 的"免确认"只是不用逐项确认，**同样先移入隔离区**，不绕过可还原设计）；
4. **可还原**：**所有分级（含 L1 与回收站）的清理一律先移入隔离区**（默认保留 7 天，可一键还原），而不是直接永久删除；**隔离区路径由用户自行指定**，可放在非系统盘上（具体规则见 3.4）。注意：隔离区与源文件同卷时，空间要等保留期结束或清空隔离区后才真正释放；
5. **全程留痕**：删了什么、多大、什么时候、能不能还原，全部写日志，并给用户一份可回滚清单；
6. **可中断**：扫描与清理都要能被用户中途停止；清理过程中断电/强退不得留下半残状态（先落清单，再逐项执行）；
7. **不联网、无广告、无遥测**：本工具全程本地运行，不上传任何数据，不弹任何推广；
8. **不碰注册表**：注册表清理风险高、收益低，"清楚注册表垃圾"一类功能明确排除（见第 8 章）；
9. **保守原则——默认不勾是常态**（用户拍板，贯穿全部清单）：只有"删除后会被自动重建、或系统本来就会自动清理"的项才允许**默认勾选**；凡属用户数据、可再下载资源、影响系统功能的项，**一律默认不勾**，由用户读完说明后自己勾。不确定的一律交给用户，工具绝不替用户做危险决定（落地规则见 5.4）。

### 1.3 术语定义

1. **清理项（CleanItem）**：一条"可清理对象"的定义，包含名称、路径/路径模式、所属分级、判据、副作用说明、还原方式；
2. **扫描（Scan）**：遍历清理项、统计其占用体积/文件数/最近修改时间的过程，只读，不改动任何文件；
3. **清理（Clean）**：对扫描结果中选中的清理项执行删除或移入隔离区的动作；
4. **分级（Tier）**：按"删掉之后会发生什么"对清理项做的归类，取值为 L1 / L2 / L3（见 2.1）；
5. **隔离区（Quarantine）**：本工具自己的暂存目录。**所有分级（L1 / L2 / L3 / 回收站）清理的对象都不是直接永久删除，而是先被移动到隔离区**（v0.6 起 L1 也进隔离区），保留 N 天后才真正释放，期间可一键还原；
6. **白名单（Allowlist）**：允许被清理的路径集合。只有命中白名单的路径才会被删除逻辑处理；
7. **禁止清单（Denylist）**：无论用户怎么勾选都不允许碰的路径集合（见 4.2），代码层面硬编码拦截；
8. **判据（Rule）**：判定一个清理项属于哪一档的唯一标准——不是"它是哪个目录"，而是"删掉之后会发生什么"。

## 2 清理对象分级（核心需求）

### 2.1 分档模型

**唯一判据**：删掉之后会发生什么。

| 分级 | 判据（删掉之后） | 默认行为 | 是否需用户确认 | 是否可还原 |
| ---- | ---- | ---- | ---- | ---- |
| **L1 一键直清** | 系统或软件自己生成的纯缓存/临时数据，会自动重建，删除无副作用 | 扫描后随"一键清理"直接执行 | 否 | 是（进隔离区） |
| **L2 推荐清理** | 属于用户的数据或可再下载的资源，删了要重新下载 / 重新登录 / 重新缓存 | 默认勾选，用户可取消 | 是（勾选） | 是（进隔离区） |
| **L3 谨慎清理** | 可能影响系统功能，或删除后不可逆 | 默认**不勾选** | 是（勾选 + 二次确认） | 是（进隔离区；不可逆项单独提示） |
| **回收站** | 单列一档：里面可能是用户手滑删掉、还想找回来的东西 | 默认**不勾选** | 是（勾选） | 是（进隔离区，保留期内可还原） |

> 说明：把"回收站"单独列一档而不是塞进 L2，是因为它的语义特殊——它不是"缓存"，而是"用户自己刚删的东西"，动机与其余各项完全不同。
> v0.6 起**所有分级统一走隔离区**（用户拍板），因此"可还原"这一列全部为"是"；代价是隔离区与源文件同卷时空间不会立即释放（见 3.4-7）。

### 2.2 L1 一键直清（初始清单）

以下对象扫描后随"一键清理"执行，不需要用户逐条确认（**仍然先移入隔离区，见 3.2-5**）：

| 名称 | 路径 | 副作用说明 |
| ---- | ---- | ---- |
| 用户临时目录 | `%TEMP%`（`C:\Users\<用户>\AppData\Local\Temp`） | 正在被占用的文件跳过并记录；无其他影响 |
| 系统临时目录 | `C:\Windows\Temp` | 同上 |
| Windows 更新下载缓存 | `C:\Windows\SoftwareDistribution\Download` | 已下载未安装的补丁会重新下载；不影响已安装更新 |
| 传递优化缓存 | `C:\Windows\ServiceProfiles\NetworkService\AppData\Local\Microsoft\Windows\DeliveryOptimization` | 系统自动重建 |
| 错误报告缓存 | `C:\ProgramData\Microsoft\Windows\WER\ReportQueue`、`ReportArchive`、`Temp` | 无 |
| 系统日志 | `C:\Windows\Logs\CBS`、`C:\Windows\Logs\DISM`、`C:\Windows\Logs\WindowsUpdate` | 排障用历史日志，删除不影响运行 |
| 内核转储 / 崩溃转储 | `C:\Windows\MEMORY.DMP`、`C:\Windows\Minidump\*`、`C:\Windows\LiveKernelReports` | **保留最近一次蓝屏转储**（按修改时间最新的 `MEMORY.DMP`，或最新一个 Minidump），更早的一律清除——既回收几个 G 到几十 G 的空间，又不至于把正在排查蓝屏的唯一线索删掉。该策略已由用户确认。<br>`LiveKernelReports` 属内核实时报告，无分析价值，全部清除 |
| 缩略图与图标缓存 | `%LocalAppData%\Microsoft\Windows\Explorer\thumbcache_*.db`、`iconcache_*.db` | 首次浏览文件夹时会重新生成（略慢）。**注意这些文件通常被 `explorer.exe` 占用**：被占用则跳过，并在报告里提示"重启资源管理器后可再次清理"——**工具不自动结束用户的 explorer.exe** |
| 平台自带临时目录 | `%LOCALAPPDATA%\Packages\*\LocalCache\Temp` 等应用临时目录 | 无 |
| 应用自身日志缓存 | **仅限内置白名单中已逐条评审过的应用日志目录**（例如 `%LocalAppData%\<某应用>\logs`），不做通配扫描 | 仅影响该软件的历史排障记录。为避免变成"扫全盘 logs"这种模糊范围，新增应用必须逐条进白名单并回答 L1 判据（见 2.2 末的设计约束） |

> 设计约束：L1 清单必须是"闭集"。新增任何 L1 项，必须在评审中回答"删掉之后会发生什么"，只有答案是"自动重建、无副作用"才允许进入。

### 2.3 L2 推荐清理（多数默认勾选，个别项默认不勾）

| 名称 | 路径 | 副作用说明 |
| ---- | ---- | ---- |
| 浏览器缓存 | Edge/Chrome：`%LocalAppData%\<厂商>\<浏览器>\User Data\<Profile>\Cache`、`Code Cache`、`GPUCache`；Firefox：`...\Profiles\*\cache2` | **不删除**密码、书签、Cookie、历史记录（Cookie 单独列出，默认保留，勾选会丢登录态） |
| 浏览器站点数据（Cookie / 登录态） | 各浏览器 `User Data\<Profile>\Cookies` | **单列一项、默认不勾**：勾选后会丢失网站登录态（需重新登录），属于用户数据而非缓存（见 5.4 保守原则） |
| 下载目录中的安装包 | `%USERPROFILE%\Downloads` 下的 `*.exe/*.msi/*.zip`，超过 N 天未访问 | 需重新下载 |
| 开发包管理器缓存 | npm `%LocalAppData%\npm-cache`、pnpm store、yarn cache、pip cache、NuGet `~\.nuget\packages` 与 `%LocalAppData%\NuGet\v3-cache`、Gradle `~\.gradle\caches`、Maven `~\.m2\repository`、Go build cache / GOMODCACHE、Cargo registry | 下次构建需重新下载依赖（耗时长、依赖网络），因此归 L2 而非 L1 |
| 旧系统残留 | `C:\Windows.old`、`$WINDOWS.~BT`、`$WINDOWS.~WS` | **安全**：它是升级时留下的旧系统副本，Windows 自己会在 10 天后自动删掉它（存储感知）。删除后失去"回退到升级前系统版本"的能力——而系统的回退窗口本身也只有 10 天。**策略：归 L2、默认勾选**；若检测到升级距今不足 10 天，**默认不勾选**并提示"再等几天，回退窗口会自动关闭" |
| 显卡驱动安装包残留 | `C:\ProgramData\NVIDIA Corporation\Downloader` 等安装器缓存 | 重新安装驱动时会重新下载 |
| 预取文件 | `C:\Windows\Prefetch` | 会短暂影响开机与程序首次启动速度，Windows 会逐步重建；**保留在 L2、默认不勾选**（用户已确认这个处理方式） |
| 浏览器/应用的崩溃转储 | `%LocalAppData%\CrashDumps`、`Google\CrashReports` 等 | 无 |

### 2.4 L3 谨慎清理（默认不勾，需二次确认）

| 名称 | 路径 / 操作 | 风险与提示 |
| ---- | ---- | ---- |
| 休眠文件 | **不是"删文件"，而是"关功能"。** 唯一执行方式：`powercfg /h off`（关闭休眠）。工具**永不直接删除 `C:\hiberfil.sys`**——该文件被系统独占并受保护，手动删除会被拒绝，`/h off` 本身就是"关闭休眠 + 释放该文件"的原子动作 | 代价明确且用户已知情：关掉休眠会连带关掉"快速启动"，开机慢几秒到十几秒，笔记本合盖久放会掉电。用户确认**不需要快速启动**，因此本项按"关闭休眠"实现。**追加硬性门禁（3.8）：必须先由用户显式授权关闭休眠，该授权成功后本项才算清理完成；用户不授权关闭 → 本项不予删除、直接跳过并标注原因**。可逆：`powercfg /h on` 可随时恢复（恢复后文件会重新生成）。**注意：只影响休眠（S4）与快速启动，不影响睡眠（S3/现代待机）与正常关机** |
| 组件存储清理 | `DISM /Online /Cleanup-Image /StartComponentCleanup` | 只能走官方命令，**禁止直接删除 WinSxS 目录**。该命令只移除已被取代的旧组件（耗时可长达十几分钟、不宜中断）；**不要加 `/ResetBase`**——加了会让所有已安装更新都无法卸载回滚，本工具不提供该开关。清理后近期更新的卸载能力可能受限，界面需注明 |
| 卸载残留目录 | `Program Files*`、`ProgramData`、`%LocalAppData%` 中确认已无对应安装的残留目录 | 需要可靠判定（注册表卸载项 + 目录名比对），否则极易误删；判定不确定的一律不列出 |
| 大文件 / 重复文件扫描 | 扫描结果列表（按体积排序，用户逐个勾选） | 纯用户决策项，工具只做展示与勾选，不做自动判定 |
| 聊天工具文件缓存 | 微信 / QQ 的 `FileStorage`、`Image`、`Video` 等缓存目录 | 极可能包含用户要留的聊天文件，必须默认不勾并给出目录明细 |
| 页面文件 | `pagefile.sys` | **信息项（不可勾选）**：仅提示占用体积，不提供任何清理动作（交由用户在系统设置中自行调整），同时列入 4.2 禁止删除项 |

### 2.5 回收站

| 名称 | 路径 | 说明 |
| ---- | ---- | ---- |
| 回收站 | **默认仅 C 盘**的 `C:\$Recycle.Bin`（其他分区需用户在设置中显式启用） | 单列一档，默认不勾选；清理时与其他项一致，**先移入隔离区**（保留期内可还原），保留期结束或用户"立即清空隔离区"后才真正释放。实现上按 SID 子目录成对处理 `$I`（元数据）与 `$R`（实体文件），**不整目录递归删除** |

### 2.6 明确不清理 / 永久禁止（Out of Scope & Permanent Denylist）

**通用不清理项**：注册表项、`C:\Windows\System32`、`C:\Windows\WinSxS`（仅允许 DISM 官方清理）、`C:\Windows\Installer`、驱动存储 `DriverStore`、`Program Files*` 正常安装目录、用户桌面/文档/图片/视频、凭据目录（`.ssh`、`.git`、浏览器密码库）、系统正在使用的文件。

**永久禁止项（用户终审拍板，最高优先级）**：

| 禁止对象 | 约束（三不原则） |
| ---- | ---- |
| **系统还原点 / 卷影副本（VSS）** | **不扫描、不展示、不删除。** 它是系统出事后的唯一退路，性质上属于"保险"而非垃圾；连"展示占用体积"也不做，避免用户顺着数字去找第三方工具清掉。代码内**不得存在任何 `vssadmin delete` / `DeleteShadow` 一类的调用路径** |

> 该禁止项不是配置项，是产品级红线：任何版本、任何开关、任何"高级模式"都不允许绕过。

## 3 功能需求

### 3.1 空间盘点（扫描）

1. 扫描 C 盘总体情况：总容量、已用、可用，并按"清理项 / 其他"做占比可视化；
2. 逐项统计：占用体积、文件数量、最近修改时间、是否可被占用（占用中的文件标记为跳过）；
3. 结果**按 L1 / L2 / L3 / 回收站分组展示**，每项给出体积与副作用说明；
4. 顶部给出汇总："本次可处理 X GB"（分"一键可清"与"勾选后可清"两个数字）；**若隔离区与 C 盘同卷，文案必须改为"将移入隔离区 X GB，保留期结束后释放"，不得直接宣称已释放**（见 3.2-6）；
5. 扫描只读，可在任意时刻中断；中断后已扫描部分仍然有效；
6. 扫描需具备性能预期：全盘扫描不超过可接受时长；可缓存上次扫描结果用于**加速展示**，但**执行清理前必须重新校验**（缓存只用于看，不用于删）。

### 3.2 一键直清（L1）

1. 用户点击"一键清理"，仅对 L1 项执行；
2. 执行过程中实时展示进度（当前项、已处理体积/实际释放体积、跳过项数）——同卷时显示"已移入隔离区"，跨卷时显示"已释放"；
3. 被占用的文件跳过并计入报告，不报错中断；
4. 执行完成展示结果页：共释放多少、清了多少文件、跳过了什么；
5. **L1 也走隔离区（v0.6 定稿）**：所谓"一键直清"指的是**不需要用户逐项确认**，而不是"绕过隔离区直接永久删除"——文件先移入隔离区，保留期内仍可还原；
6. **同卷不释放的如实提示**：若隔离区与源文件位于**同一卷**（例如都还在 C 盘），本次操作不会立即降低该盘占用，界面必须显示"已移入隔离区 X GB，将在保留期结束或清空隔离区后释放"，并建议把隔离区改到非系统盘。

### 3.3 选择清理（L2 / L3 / 回收站）

1. 以勾选列表形式呈现，L2 默认勾选、L3 与回收站默认不勾；
2. 每项展示：名称、体积、路径、副作用说明（L3 需展开可见）；
3. 全选/反选只作用于当前分级，禁止"一键全选所有级别"；
4. L3 执行前必须二次确认，确认文案写清"会发生什么"而不是"是否继续"；
5. **不记忆勾选状态**：每次扫描都回到默认勾选状态（L2 勾、L3 与回收站不勾），避免上次的勾选被自动沿用（见 5.4-2）。

### 3.4 隔离区与还原

**核心诉求（用户明确要求）：隔离区位置由用户自己指定。**

1. **路径可自定义**：设置页提供"隔离区位置"选择项（HandyControl 控件 + 系统文件夹选择），用户可指向任意本地目录（如 `D:\SpaceMaidQuarantine`）；默认值 `%LocalAppData%\SpaceMaid\Quarantine`；
2. **路径校验**（选定即校验，不通过不允许保存）：
   - 必须是**本地固定磁盘**的绝对路径；网络路径、映射盘、可移动介质给出明确警告（U 盘拔了就不能还原）；
   - 目标位置必须**可写**、可创建子目录；只读或权限不足时提示并拒绝；
   - **跨卷隔离必须预留空间**：此时流程是"复制 → 校验 → 删源"，目标卷剩余空间必须 ≥ 本次待隔离体积，不足直接拒绝而不是清到一半失败；**同卷隔离只是移动目录条目、几乎不额外占空间**，不要因此误拒；
   - 若隔离区仍落在 **C 盘**，弹出提醒："放在 C 盘不会真正释放 C 盘空间，建议改到其他盘"——**提示但不强制**（用户有权坚持）；
   - 禁止把隔离区设到系统目录、清理项自身所在目录、磁盘根目录（只能在选定目录下建 `SpaceMaid\Quarantine` 子目录，不污染用户目录结构）；
   - 隔离区不能与"禁止清单"（4.2）中的任何路径重叠。
3. **隔离实现**：按 `<隔离区>\<yyyyMMdd-HHmmss>\` 分批存放；同卷使用原子移动，**跨卷为"复制 → 校验大小/哈希 → 删除源文件"**，任一步失败则保留源文件并在报告中标注"未清理成功"；
4. **映射表**：每次清理写一份映射表（原始绝对路径、所在卷序列号、体积、时间、所属分级），存入隔离区目录内（JSON 原子写）。该表是还原的唯一依据，程序异常退出时必须保证其完整；
5. **保留期与释放**：默认保留 **7 天**（已确认）。**本工具无常驻进程、也不注册计划任务，因此"到期释放"是惰性执行的——在下一次启动或下一次扫描时释放已到期的批次**，界面在启动时提示"隔离区有 X GB 已到期，可释放"；用户随时可"立即清空"（需二次确认，文案写明不可还原）；
6. **一键还原**：按映射表把文件搬回原位置；若原位置已存在同名文件、原卷不可用或空间不足，逐条报告冲突并让用户选择处理方式，不静默覆盖；
7. **L1 也进隔离区（v0.6 定稿）**：L1 / L2 / L3 与回收站清理的对象统一先移入隔离区，规则一致、全部可还原。由此带来两个必须处理好的后果：
   - **同卷不释放**：隔离区若与源文件同卷（默认都在 C 盘），移动后该盘占用不会立刻下降——界面要如实显示"已移入隔离区 X GB，尚未释放"，并建议把隔离区改到非系统盘（校验规则第 4 条已提示）；
   - **空间预检按"跨卷需复制"的口径做**：同卷移动无需额外空间，跨卷必须预留；两种情况下都不能向用户宣称"C 盘立刻腾出 X GB"（校验规则第 3 条）；
8. **可逆性对用户可见**：清理报告中每项标注"可从隔离区还原 / 已永久删除"，并给出隔离区当前占用与到达释放时间。

### 3.5 日志与报告

1. 全程写日志：`D:\logs\SpaceMaid\`（与既有工具一致，按日分文件），记录扫描、清理、跳过、还原、异常；
2. 每次清理生成一份"清理报告"（本次释放总量、按分级明细、跳过项、可还原项），可在界面内查看；
3. 日志滚动保留（建议 30 天），不无限增长；**同样在下次启动时惰性清理**（本工具无常驻进程）；

### 3.6 权限处理（v0.4 定稿：固定管理员运行）

1. **程序清单固定为 `requireAdministrator`**：SpaceMaid.exe 直接以管理员身份启动（用户拍板："直接让 exe 必须通过管理员打开就行"）。本次运行的全部清理项都在同一个管理员会话内完成，**不出现"清到一半提示需要提权"**的情况；
2. 程序启动时自检当前是否具备管理员权限：不具备（例如被特殊方式以普通身份拉起）则给出明确提示并阻止进入清理流程，**不做静默提权、不常驻高权限服务、不安装任何系统服务**；
3. UAC 弹窗由系统弹出，程序不做任何绕过或"记住授权"的处理；
4. 界面需在首次启动时用一句话说明"本工具需要管理员权限，因为要清理系统临时目录与更新缓存"，避免用户对 UAC 弹窗产生疑虑。

### 3.7 干跑（Dry-run）

提供"只预览不处理"模式：展示本次将要处理的完整文件清单与体积（含"移入隔离区"或"执行命令"两种动作），供用户与开发者核对；该模式也用于开发自测。

### 3.8 前置授权闸门：休眠文件（用户强制要求）

1. **执行方式不是"删文件"，而是"关功能"**：`C:\hiberfil.sys` 是休眠功能的存储体，被系统独占持有，手工删除会被系统拒绝、也可能造成休眠状态不一致。本项的唯一执行方式是 `powercfg /h off`——**这条命令本身就完成了"关闭休眠 + 释放该文件"，不存在也不需要"先关功能、再单独删文件"的第二步**。工具**永不把 `hiberfil.sys` 当作删除目标**（4.2 已把它列入禁止删除项）。顺带说明：此举只影响休眠（S4）与快速启动，**不影响睡眠（S3/现代待机）与正常关机**；
2. **硬性门禁**（用户原话："必须要硬性先执行关闭，然后才能删除；如果不勾关闭，这一项不予删除"）：
   - 勾选"休眠文件"后，必须出现**独立的授权步骤**，写明后果：将关闭休眠功能、随之失去快速启动、开机变慢、笔记本合盖久放会掉电；以及**该操作可逆**（`powercfg /h on` 可恢复）；
   - 用户必须显式同意。**未同意 → 本项一律不执行，直接跳过，并在报告中标明"未授权关闭休眠，已跳过"**；
   - 代码中不存在"只删文件不关功能"或"先删文件后关功能"的执行路径。
3. **执行与校验**（exe 已固定管理员运行，无需额外提权）→ 执行 `powercfg /h off` → 校验返回码 → 校验 `hiberfil.sys` 是否已消失 → 记录释放体积（关闭前后磁盘可用量差值）。
4. **失败处理**：无管理员权限、命令被拒、组策略限制等，一律判为失败：**不重试、不降级为直接删文件**，报告中写明失败原因与手动处理方式。
5. **可逆提示**：界面与报告中同时给出"如何恢复休眠（`powercfg /h on`）"。
6. **保守替代（可选）**：若用户只想缩体积、仍想保留快速启动，可在该项说明里提到 `powercfg /h /type reduced`（文件缩到内存约 40%，**不删除文件**，因此不计入"已释放"数字，只标注"已缩小至 X GB"）。本项默认执行的是 `/h off`，与用户"不需要快速启动"的表态一致。

### 3.9 清单导出与执行后复核（本项目约定的验收协作流程）

用户明确的协作方式：**工具先把完整的待清理清单列出来 → 用户人工审阅 → 用户自己执行清理 → 工具复核清理结果 → 审核完成**。任何环节都不允许工具在未经审阅的情况下自行删除。

1. **清单导出（Dry-run，只读，绝不删）**：
   - 扫描完成后可导出完整清单，默认写到 `D:\logs\SpaceMaid\清单\<时间戳>\`（与仓库其他工具的日志路径约定一致），同时输出两种格式：
     - `清单.md`——给人看：按 L1 / L2 / L3 / 回收站分组，逐条列出名称、体积、路径、判定理由、是否可还原、跳过原因；
     - `清单.csv`——给机器复核：至少含 `分级,名称,原始路径,体积字节,文件数,最后修改时间,动作(移入隔离区/执行命令),是否可还原` 这些列；
   - 清单必须**穷尽**：凡是本次会被删除或移动的路径都要列出来，不允许出现"清单里没有、执行时却删了"的项；
   - 文件级条目数量过大时可聚合为"目录 + 文件数 + 总体积"，但聚合层级必须能追溯到具体目录；处在边缘状态（小于阈值、近期修改）的文件另附明细；
   - 导出清单时**不执行任何写操作**：不禁用、不移动、不重命名任何目标文件。
2. **人工审阅**：用户查看 `清单.md` 并确认；有异议时可在执行前调整勾选或排除项，工具重新导出清单。
3. **用户执行清理**：由用户在界面中点击执行——**"导出清单"与"执行清理"之间不存在自动衔接，必须有明确的人工动作**。
4. **执行后复核（Review）**：
   - 清理结束后，工具重新扫描同一批清理项，与执行前的清单逐条比对，输出**复核报告**：
     - 已清理：数量、体积、逐条确认（路径已不存在，或已移入隔离区并能对上映射表）；
     - 未清理 / 跳过：原因（文件被占用、权限不足、未授权关闭休眠、用户取消勾选等）；
     - 异常：清单中有、但扫描结果状态不明的项——必须逐条列出，不允许静默忽略；
   - 复核报告同样写入 `D:\logs\SpaceMaid\`，并与执行前清单做差值对照；
   - **复核报告就是"审核完成"的依据**：只有复核报告确认清单内项目全部按预期处理（或未处理原因已明确解释），本次清理才算验收通过。
5. **禁止项**：工具不得提供"跳过清单直接清理""静默后台清理""定时自动清理"等绕过人工审阅的能力。

## 4 安全设计

### 4.1 删除执行链路

1. **路径规范化**：展开环境变量、处理长路径（`\\?\` 前缀）、解析符号链接与junction，**不跟随链接删除目标**；
2. **白名单校验**：待删路径必须是某个清理项路径的子路径；路径比较使用规范化后的绝对路径，杜绝 `..` 穿越；
3. **禁止清单拦截**：命中禁止清单（4.2）立即中止该项并记日志；
4. **年龄与占用判定**：可配置"只清超过 N 天未修改的文件"，规避正在被写入的文件；被占用文件跳过；
5. **执行顺序**：先写清单（待删列表）→ 逐项执行 → 每项写结果 → 汇总；任一步失败不影响其余项；
6. **不递归删除用户目录**：凡指向用户数据目录的清理项，必须指定具体子目录（如 `Downloads\*.exe`），禁止整目录递归。

### 4.2 禁止清单（代码级硬约束）

`C:\Windows\System32`、`C:\Windows\SysWOW64`、`C:\Windows\WinSxS`（仅允许 DISM）、`C:\Windows\Installer`、`C:\Windows\Fonts`、`C:\Program Files`、`C:\Program Files (x86)` 的正常安装目录、`C:\Windows\System32\DriverStore`、用户桌面/文档/图片/视频、`.ssh`、`.git` 等凭据与版本库目录、当前正在运行的程序的可执行文件。

**追加禁止项（v0.3）**：

- `C:\hiberfil.sys`——**禁止作为删除目标**。本项只能通过 `powercfg /h off` 释放，删除层不认识这个路径；即便用户手改配置指向它，也会被拦截（见 3.8）；
- `C:\pagefile.sys` 与 `swapfile.sys`——只读展示，禁止删除；
- 系统还原点 / 卷影副本的存储位置（`System Volume Information` 及各卷 VSS 快照）——禁止访问、禁止删除。

> 该清单以常量形式硬编码在删除层，**不是配置文件**，任何 UI 与配置都不能突破它。

### 4.3 用户侧防误操作

1. 危险操作（L3、回收站、关闭休眠、清空隔离区）必须二次确认，确认文案描述后果；
2. 设置项"清空隔离区"需输入确认或勾选"我确认无法还原"；
3. 所有体积数字（本次可处理量 / 实际释放量 / 已移入隔离区量）在执行前后都要对照展示，出现负增长或异常偏大时给出警告；
4. **永久禁止项在扫描层就不出现**：系统还原点/卷影副本不进扫描结果、不进界面列表、不进导出报告，用户没有任何入口可以勾选它（见 2.6）；
5. **不提供任何"绕过确认"的开关**：不存在"高级模式/强制清理/隐藏参数"来跳过二次确认或禁止清单。

## 5 交互与界面（建议方案）

### 5.1 主界面结构

单窗口三段式：

1. **顶部：磁盘总览**——C 盘容量条 / 环形占用图 + 关键数字（总容量、已用、可用、本次可处理量）；
2. **中部：分级清单**——按 L1 / L2 / L3 / 回收站分组折叠展示，每项一行（名称、体积、路径、副作用），L2/L3/回收站带勾选框；
3. **底部：操作栏**——左"重新扫描"、中"本次可处理 X GB"（同卷时标注"尚未释放"）、右主按钮"一键清理（L1）"与次按钮"清理选中项"；
4. **设置**——隔离区位置（可自定义路径，含校验提示）、保留天数、隔离区当前占用与"立即清空"、清理报告与日志入口。

### 5.2 交互细节

1. 扫描过程有明确进度与可中断入口，而非转圈等待；
2. 清理过程实时输出日志流，完成后给结果页（实际释放量 + 已移入隔离区量 + 可还原项 + 报告入口）；
3. 所有副作用说明用用户能看懂的话写，不写"可能影响系统稳定性"这类空话；
4. 空态、加载态、无权限态、清理完成态都要有明确设计；
5. 支持"扫描中不阻塞界面"，长任务不冻结窗口。

### 5.3 视觉规范

1. 走统一设计系统：设计令牌集中在一处（颜色、圆角、间距、字号），控件样式统一，禁止逐处硬编码；**控件一律 HandyControl**（主题与令牌集中管理），HandyControl 确实未提供时才用 WPF 原生控件对齐样式，禁止自绘伪控件；
2. 层级清晰：主数字（本次可处理量/实际释放量）显著，次要信息（路径、副作用）弱化，留白充足；
3. 危险动作与安全动作在视觉上必须可区分（主按钮 / 次按钮 / 危险按钮三级），配色克制，**不做大面积红绿色块**；但**风险文案允许用红色文字做单点强调**（见 5.4）；
4. 每种状态（安全 / 注意 / 危险）在列表里用一致的视觉语言表达，用户扫一眼就知道哪些是"随手可清"、哪些是"要读一下"；
5. 沿用 DshLauncher 已有的浅色设计令牌体系，保持个人工具家族的一致性（令牌集中在 `Themes/` 下，禁止逐处硬编码）。

### 5.4 文案与风险标注规范（v0.5 新增）

1. **默认勾选门槛（保守原则的落地）**：只有判据为"删除后自动重建 / 系统本来就会自动清理"的项才允许默认勾选（当前仅：L1 全部——L1 本身没有勾选框，随"一键清理"执行；以及 L2 中的 `Windows.old` 等少数项）；其余全部默认不勾，包括各类缓存、下载目录、聊天缓存、休眠文件、回收站；
2. **不记忆勾选状态**：每次启动/每次扫描都重置为默认勾选状态——避免上次勾过的 L3 项在用户没注意时被自动沿用（记住勾选与保守原则冲突，故不采用）；
3. **风险标注写法**：L3 项与任何不可逆动作，在名称后用括号写明**动作性质**，并用**红色文字**强调，例如：
   - `休眠文件（仅关闭功能，不删文件）`
   - `回收站（保留期内可还原，清空隔离区后不可还原）`
   - `Windows.old（删除后无法回退到升级前系统版本）`
   - `组件存储清理（清理后无法卸载已安装更新）`
4. **必须写恢复方式**：每个 L3 项在界面里就地给出恢复办法（如"恢复：`powercfg /h on`"），让用户在动手前就知道能不能回头；
5. **不写空话**：禁止"可能影响系统稳定性"这类无信息量的提示，必须写清"会发生什么"；
6. **红色只用于风险文案**，不用于大面积底色，保持"商用级"观感（与 5.3 一致）。

## 7 验收标准

1. **功能**：L1 一键清理可在无用户逐项确认的情况下完成；L2 / L3 / 回收站的勾选清理生效；隔离区还原能把文件放回原位且可打开；
2. **安全**：在测试机上按 3.9 的流程，**由用户执行**清单内的清理动作 + 重启，系统可正常启动、常用软件正常；禁止清单内的路径在任何输入下都不被删除；
3. **量级**：L1 清理结果与 Windows"存储感知 / 临时文件"统计量级相当（允许差异，但不得出现数量级偏差）；
4. **留痕**：每次清理都产生日志与报告，报告可列出每项的体积与可还原状态；
5. **体验**：全流程无弹窗广告、无联网请求；界面为统一设计系统下的成品观感（满足"商用级"要求）；
6. **健壮**：清理过程中强杀进程 / 断电，重启后隔离区与映射表仍可用；
7. **隔离区自定义路径**：把隔离区改到 D 盘等非系统盘后，L1/L2/L3 清理确实降低了 C 盘占用，且能按映射表还原回原位置；隔离区不可写、空间不足、指向可移动介质时，在**执行前**给出明确提示或拒绝，不出现"清到一半失败"；
8. **技术栈**：界面全部由 HandyControl 控件搭建（HandyControl 未提供的功能才允许使用 WPF 原生控件），不得出现自绘伪控件；清理内核不依赖界面层，可独立调用；
9. **休眠项的授权闸门**：勾选休眠文件但未通过授权步骤时，工具**不执行任何动作**，报告中出现"未授权关闭休眠，已跳过"；通过授权后 `powercfg /h off` 成功执行且 `hiberfil.sys` 消失；全流程不存在任何"直接删除 `hiberfil.sys`"的代码路径（代码审查可验证）；
10. **永久禁止项**：全量扫描结果、界面列表、导出报告中**不出现**系统还原点 / 卷影副本相关条目；代码库中不存在 `vssadmin delete shadows` 或任何 VSS 删除 API 的调用（静态检索可验证）；
11. **权限**：exe 启动即弹一次 UAC 并以管理员身份运行；被以普通权限拉起时明确拒绝进入清理流程；全流程不再出现第二次提权提示；
12. **清单与复核（本项目的审核依据）**：dry-run 导出的清单过程中不含任何写操作，且与执行时实际处理的路径完全一致——不存在"清单里没有、执行时却删了"的项；执行后复核报告能逐条给出"已清理 / 未清理及原因 / 异常"，并与执行前清单做差值对照，异常项必须逐条列出而非静默忽略；
13. **保留策略**：蓝屏转储只清更早的、最近一次仍在；`Windows.old` 在升级不足 10 天时不默认勾选；
14. **保守原则**：所有"用户数据 / 可再下载 / 影响系统功能"的项默认均不勾选；不存在任何自动沿用上次勾选状态的机制；每个 L3 项的界面文案里都能看到动作性质（括号）与恢复方式；
15. **统一隔离**：L1 / L2 / L3 / 回收站四类的清理对象都能在隔离区找到并还原；同卷场景下界面如实提示"尚未释放"，**不谎报释放量**。

### 9.2 三个"影响系统能力"项的最终结论（v0.3 定稿）

用户提出的疑问："休眠文件、`Windows.old`、系统还原点是不是其实都挺安全、清了一般没事？"——**回答：前两个基本认同（休眠另有代价）；第三个恰恰相反，因此它被列为永不删除项。**

| 项 | 安全性结论 | 依据 | 最终落库位置 |
| ---- | ---- | ---- | ---- |
| `C:\Windows.old` | **安全** | 升级时留下的旧系统副本，Windows 自己就计划 10 天后删掉它；删除唯一代价是失去"回退旧版本"的能力，而系统给的回退窗口本来就只有 10 天 | **L2、默认勾选**；升级不足 10 天时默认不勾并提示（2.3） |
| `C:\hiberfil.sys` | **安全，但有可感知代价；执行有硬性前置条件** | 关掉休眠会连带关掉"快速启动"（用户已明确表示不需要）；好处是完全可逆（`powercfg /h on`）。用户要求：**必须先关闭休眠功能才能释放该文件，不授权关闭就不删** | **L3、默认不勾 + 前置授权闸门**（2.4、3.8）；工具永不直接删该文件，4.2 已将其列为禁止删除项 |
| 系统还原点 / 卷影副本 | **不属于清理对象，是保险** | 占用 3%~10%，但系统被驱动或软件搞坏时，它是唯一能把机器拉回原状的东西，删除后不可逆。用户结论："列为永不删除项，不能扫描、不能勾选，绝对不放进可删除集合" | **永久禁止项**：不扫描、不展示、不可勾选、永不删除（2.6、4.2、4.3-4、第 7 章验收第 10 条） |
