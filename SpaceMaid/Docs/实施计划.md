# SpaceMaid 实施计划（TDD 任务级）

> **给执行者（人或 AI 子代理）**：本计划按任务顺序执行，**每个任务先写失败测试再写实现**（TDD），完成后 `dotnet test` 全绿再提交。
> 每个任务的信息来源：本文件该任务的「Files / Interfaces / Steps」+ `Docs/设计文档.md` 对应章节（接口签名以设计文档 §3–§10 为准）。
> 需求基线：`Docs/需求.md` v0.7（已冻结）。**任何实现不得偏离需求；发现需求与设计冲突时停下来问，不要自行改需求。**

**Goal:** 交付一个可运行、可验证的 C 盘清理工具：内核可单测、界面商用级、安全不变量由测试守住。

**Architecture:** `SpaceMaid.Core`（纯逻辑内核，无 WPF）+ `SpaceMaid.App`（WPF + HandyControl，引用 Core）。所有落地动作经 `SafetyGate`；所有清理先进隔离区；清单是执行的唯一输入。

**Tech Stack:** .NET 8（`net8.0-windows`）/ WPF / HandyControl 3.5.1 / xunit 2.9.2 / Microsoft.NET.Test.Sdk 17.11.1 / Release 单文件 win-x64。

## Global Constraints（每个任务都隐含遵守）

- 目标框架 `net8.0-windows`；`Nullable=enable`；`ImplicitUsings=enable`；解决方案用 `slnx`。
- **Core 不得引用 WPF**（`using System.Windows*` 一律禁止），由 T15 的静态检索测试守住。
- **不得出现**字符串 `vssadmin`、`DeleteShadow`（I-5）；**不得**实现 `/ResetBase`。
- **不得**新增任何"绕过确认"的开关/参数。
- 删除类 API（`File.Delete` / `Directory.Delete`）**只能**出现在 `SpaceMaid.Core/Quarantine/QuarantineStore.cs`（I-1）。
- 一切 IO 测试的根目录必须在 `%TEMP%\spacemaid-tests-<guid>` 下，`finally` 中删除；**测试不得触碰真实系统目录**。
- 提交信息用中文，前缀 `feat:` / `fix:` / `docs:` / `test:` / `chore:`。
- 界面控件优先 HandyControl，HC 没有的才用 WPF 原生控件；不得自绘伪控件。
- 临时路径禁止写进源码（除 `%VAR%` 模板与默认值）。
