## 1 设计目标与约束

### 1.1 设计目标

1. **安全不可绕过**：所有落地动作都经过同一道安全闸门（3.3 的不变量 I-1…I-6），任何 UI、配置、命令行参数都不能绕过；
2. **内核可单测**：清理逻辑 100% 位于 `SpaceMaid.Core`，零 WPF 依赖；文件系统、时钟、卷信息、命令执行全部为接口，测试可注入假实现或使用临时目录；
3. **进程轻量**：无常驻线程、无服务、无计划任务；一切"定时"语义（隔离区到期释放、日志滚动）都降级为**下次启动惰性执行**；
4. **可验证**：需求第 7 章的每条验收标准都能指向一个具体测试（见第 12 章追溯矩阵）。

### 1.2 关键设计决策（含理由）

| 编号 | 决策 | 理由 |
| ---- | ---- | ---- |
| D-1 | 内核与界面**分程序集**：`SpaceMaid.Core`（类库）+ `SpaceMaid.App`（WPF） | 需求 1.2/9.1 要求内核独立、界面与内核解耦；且让 90% 逻辑可脱离 UI 单测 |
| D-2 | 只读 CLI **内置于 App.exe**（`--dry-run` / `--report`），不另建 CLI 工程 | 保持单二进制发布；CLI 仅写文件不碰控制台，避开 WinExe 无控制台的问题；删除动作永远只在 GUI 里由用户点击触发（需求 9.1） |
| D-3 | **不存在"永久删除"代码路径**，除隔离区过期释放 | 需求 1.2-4/3.4-7：所有分级统一先进隔离区。因此删除 API 只允许出现在 `QuarantineStore` 一个类里，并用静态检索测试守住 |
| D-4 | 系统还原点/VSS **在 Catalog 里根本不存在条目**，同时代码库禁止出现 `vssadmin` 字符串 | 需求 2.6/4.2/7 章第 10 条：不扫描、不展示、不可勾选；"代码里不存在"可被测试静态断言 |
| D-5 | 休眠项建模为 **Command 动作 + 授权闸门**，而非文件清理项 | 需求 3.8：`hiberfil.sys` 禁止作为删除目标，`powercfg /h off` 是"关功能" |
| D-6 | 体积口径分两种：**跨卷=已释放**、**同卷=已移入隔离区（未释放）** | 需求 3.2-6/3.4-7：不得谎报释放量 |
| D-7 | 清单（清单.md/csv）是**执行的输入**而非旁路产物：执行器只处理清单里的条目 | 需求 3.9：不允许出现"清单里没有、执行时却删了"的项 |
| D-8 | 风险标注用核心层提供的**结构化文案**（`ActionNote` + `SideEffect` + `RestoreHint`），界面只负责着色 | 需求 5.4：文案与视觉分离，文案可被单测断言 |

## 3 安全设计（不可破坏的不变量）

### 3.1 不变量

| 编号 | 不变量 | 守住方式 |
| ---- | ---- | ---- |
| **I-1** | 任何文件移动/删除**必须**先经 `SafetyGate.Authorize(path, item)` 返回 `Allowed` | 静态检索测试：`Execution`/`Quarantine` 中所有落地调用点都先出现 `Authorize`；`QuarantineStore` 是唯一允许调用删除 API 的类 |
| **I-2** | **禁止清单是代码常量**，不是配置；命中即拒绝并记日志 | `Denylist.IsDenied(path)` 在任何白名单判定**之前**执行（先拒后允） |
| **I-3** | 清理项只能来自 `CleanItemCatalog`（闭集）；`DefaultChecked=true` 只允许"自动重建/系统自动清理"判据 | `CatalogValidator` 在单测中对每个条目断言判据字段；L1 条目必须标 `AutoRegenerated` |
| **I-4** | `hiberfil.sys` 永远是禁止删除项；休眠只能经 `HibernateGate` 的授权闸门执行 | Denylist 常量 + `HibernateGateTests`（未授权必须直接跳过且不调用 `CommandRunner`） |
| **I-5** | 系统还原点/VSS：无条目、无扫描、无展示；代码库不出现 `vssadmin` / `DeleteShadow` | 静态检索测试（源码级字符串断言，同时满足需求 7 章第 10 条"可静态检索验证"） |
| **I-6** | 不存在"绕过确认"的开关（无高级模式/强制参数） | 代码审查 + 静态检索（无 `force` 布尔开关贯通到执行器） |

### 3.2 路径规范化（`PathNormalizer`）

顺序固定，任一步失败即判 `Unsafe`：

1. 空/空白 → 拒绝；
2. 展开 `%VAR%`（仅限已登记的环境变量表）与 `~`；
3. 拒绝含**未展开变量**与**通配符**的最终落地路径（`*`、`?` 只允许出现在 TargetRule.Pattern，不允许出现在落地路径）；
4. `Path.GetFullPath` 规范化（消除 `.`、`..`、重复分隔符）；
5. 去掉尾部目录分隔符；启用长路径前缀（`\\?\`）由文件系统层统一加；
6. **不解析**符号链接/junction 的目标（不做 `ResolveLinkTarget` 替换）；改为：落地前检测路径自身及其任一祖先是否为重解析点，**是则拒绝并在报告中标注**（避免"顺着链接删到别处"）；
7. 结果必须是**绝对路径**且位于某个 `TargetRule.Path` 的子树内。

### 3.3 禁止清单（`Denylist`，硬编码）

```
C:\Windows\System32 / SysWOW64 / WinSxS / Installer / Fonts / System32\DriverStore
C:\Program Files / Program Files (x86)        （正常安装目录；L3 卸载残留项只允许"已确认无主的目录"单独授权，见 5.4）
C:\hiberfil.sys、C:\pagefile.sys、C:\swapfile.sys
各卷 System Volume Information 与 VSS 快照
%USERPROFILE% 及其子目录（桌面/文档/图片/视频/下载根目录本身；仅允许具体的文件级 TargetRule）
.ssh / .git / %APPDATA% 下的凭据目录
任何"正在被占用"的文件（运行期判定，见 5.3）
```

### 3.4 `SafetyGate`

```csharp
public enum SafetyVerdict { Allowed, DeniedByDenylist, OutsideAllowlist, UnsafePath, ReparsePoint, NotAuthorized }

public sealed record SafetyDecision(SafetyVerdict Verdict, string Reason)
{
    public bool IsAllowed => Verdict == SafetyVerdict.Allowed;
}

public sealed class SafetyGate
{
    public SafetyGate(IFileSystem fs, ILogSink log);
    public SafetyDecision Authorize(string candidatePath, CleanItemDefinition item);
}
```

判定顺序（**先拒后允**，顺序不可调整）：`UnsafePath` → `DeniedByDenylist` → `ReparsePoint` → `OutsideAllowlist`。

## 4 领域模型（`SpaceMaid.Core/Models`）

```csharp
public enum CleanCategory { L1OneClick, L2Recommended, L3Cautious, RecycleBin }

public enum ItemRisk { Safe, Caution, Dangerous }      // 对应 5.4 的"安全/注意/危险"三态视觉

public enum CleanActionKind
{
    Quarantine,                  // 移入隔离区（绝大多数）
    HibernateOff,                // powercfg /h off（授权闸门）
    DismComponentCleanup,        // DISM 官方清理
    InformationalOnly            // 只展示不执行（pagefile.sys）
}

public enum TargetKind { DirectoryContents, DirectoryTree, FileGlob, FixedFile, RecycleBin }

public sealed record TargetRule
{
    public required TargetKind Kind { get; init; }
    public required string Path { get; init; }          // 支持 %VAR%
    public string Pattern { get; init; } = "*";
    public bool Recurse { get; init; }
}

public sealed record CleanItemDefinition
{
    public required string Id { get; init; }             // 稳定标识，用于清单/映射表
    public required CleanCategory Category { get; init; }
    public required string DisplayName { get; init; }
    public required ItemRisk Risk { get; init; }
    public required CleanActionKind ActionKind { get; init; }
    public required IReadOnlyList<TargetRule> Targets { get; init; }
    public string ActionNote { get; init; } = "";        // 括号内的"动作性质"：仅关闭功能，不删文件
    public string SideEffect { get; init; } = "";        // 人话后果说明
    public string RestoreHint { get; init; } = "";       // 恢复方式（L3 必填）
    public bool DefaultChecked { get; init; }            // 保守原则：默认多为 false
    public bool AutoRegenerated { get; init; }           // L1 判据字段（默认勾选门槛的依据）
    public TimeSpan? MinAge { get; init; }               // 只处理超过 N 天未修改的文件
    public bool KeepsNewest { get; init; }               // 保留最新一份（蓝屏转储）
    public bool RequiresElevation { get; init; }
    public string? AvailabilityNote { get; init; }      // 不可用时的说明（如"升级不足 10 天，默认不勾"）
}
```

### 4.1 清单闭集（`CleanItemCatalog`）

按需求 2.2/2.3/2.4/2.5 逐条登记，**Id 一经发布不得复用**（映射表与清单靠它对应）：

| Id | 分级 | 关键字段 |
| ---- | ---- | ---- |
| `l1.user-temp`、`l1.windows-temp` | L1 | `AutoRegenerated=true, DefaultChecked=true` |
| `l1.wu-download`、`l1.delivery-optimization`、`l1.wer`、`l1.cbs-logs` | L1 | 同上 |
| `l1.dumps` | L1 | `KeepsNewest=true`（保留最近一次） |
| `l1.thumb-cache` | L1 | `SideEffect` 写明 explorer 占用与重启提示 |
| `l1.packages-temp`、`l1.app-logs-<app>` | L1 | 应用日志**逐条**登记，禁止通配 |
| `l2.browser-cache`、`l2.downloads-installers`、`l2.dev-caches`、`l2.windows-old`、`l2.driver-downloader`、`l2.prefetch`、`l2.crash-dumps` | L2 | 仅 `l2.windows-old` 默认勾选（+10 天窗口判定），其余默认不勾 |
| `l2.browser-cookies` | L2 | 单列，默认不勾（登录态属用户数据） |
| `l3.hibernate`（`HibernateOff`）、`l3.component-store`（`DismComponentCleanup`）、`l3.orphan-app-dirs`、`l3.large-files`、`l3.duplicate-files`、`l3.chat-cache`、`l3.pagefile`（`InformationalOnly`） | L3 | 全部 `DefaultChecked=false`，`ActionNote`/`SideEffect`/`RestoreHint` 必填 |
| `rb.recycle-bin` | RecycleBin | 默认不勾；`TargetKind=RecycleBin`，仅 C 盘（`%SystemDrive%`） |

> **不存在**任何 VSS/还原点条目（I-5）。

### 4.2 清单自检（`CatalogValidator`）

对每个条目运行，任一失败即单测红：

1. `Id` 唯一、非空、小写点分；
2. `Category == L1OneClick` ⇒ `AutoRegenerated == true` 且 `DefaultChecked == true`；
3. `DefaultChecked == true` ⇒ `AutoRegenerated == true`（**保守原则的机器化表达**）；
4. `Risk != Safe` ⇒ `ActionNote` 与 `RestoreHint` 非空；
5. `Targets` 非空，且每个 `TargetRule.Path` 展开后不在 `Denylist` 内；
6. `ActionKind == InformationalOnly` ⇒ `DefaultChecked == false`；
7. 全库无字符串匹配 `(?i)vss|shadow|restore point|还原点`（I-5）。

## 5 扫描引擎（`Scanning`）

```csharp
public sealed record ScanRequest(IReadOnlyList<CleanItemDefinition> Items, bool IncludeRecycleBin);
public sealed record ScanProgress(string ItemId, string DisplayName, long BytesSoFar, int FilesSoFar);
public sealed record ScanFile(string Path, long Size, DateTimeOffset LastWrite, CleanActionKind Action);
public sealed record ScanEntry(CleanItemDefinition Item, long TotalBytes, int FileCount, int SkippedCount,
                               IReadOnlyList<ScanFile> Files, bool Available, string? UnavailableReason);
public sealed record VolumeSnapshot(string Drive, long TotalBytes, long FreeBytes);
public sealed record ScanReport(IReadOnlyList<ScanEntry> Entries, VolumeSnapshot Volume, DateTimeOffset ScannedAt);

public interface IScanEngine
{
    Task<ScanReport> ScanAsync(ScanRequest request, IProgress<ScanProgress>? progress, CancellationToken ct);
}
```

### 5.1 规则

1. **只读**：扫描阶段只做枚举与 `FileInfo`，不写入、不改名、不加属性（需求 3.9-1）；
2. **可中断**：每 N 个文件检查 `ct`；中断后已扫描部分由调用方保留在内存即可（不落盘）；
3. **年龄过滤**：`MinAge` 非空时只收 `LastWrite < now - MinAge`；被过滤掉的不进清单（但在条目上记 `SkippedCount` 原因）；
4. **保留最新一份**：`KeepsNewest=true` 时按 `LastWrite` 倒序，最新那个不进结果，其余进；
5. **Windows.old 10 天窗口**：`l2.windows-old` 额外判定目录 `CreationTime`/`LastWriteTime`，不足 10 天时 `DefaultChecked=false` 并在 `AvailabilityNote` 给出提示（由 `ScanningRules` 计算，界面直接展示）；
6. **不可用项**：目标路径不存在（如没有 `Windows.old`）→ `Available=false`，界面灰显，不参与清单；
7. **占用检测**：扫描阶段用"尝试以只读+Delete 共享方式打开"判定占用；被占用文件在落地阶段会被跳过（见 5.3）。

### 5.2 大文件 / 重复文件（L3）

`l3.large-files`：扫描固定深度内的文件，按体积降序取 Top N（默认 200），全部进清单、默认不勾、需用户逐个勾选；
`l3.duplicate-files`：只对 `Size` 相同的分组做**首段+末段哈希**，再对候选做全文件 SHA-256；**每组保留第一个（最早创建的），其余列出**；不做自动勾选。

### 5.3 落地阶段（`CleanExecutor` 内的逐项判定）

对清单中每个文件，落地前依次判定：`SafetyGate` → 存在性 → 占用（打开失败/ERROR_SHARING_VIOLATION）→ 移入隔离区。失败即记入 `SkippedFiles` 与原因，**不中断其它文件**（需求 3.2-3）。

### 5.4 卸载残留（`l3.orphan-app-dirs`，最保守口径）

同时满足才列出：① 目录名 ≠ 任何已安装程序的 DisplayName/InstallLocation 目录名；② 注册表卸载键（HKLM/HKCU 的 `Uninstall` 子树）中不存在指向该目录的 `InstallLocation`/`UninstallString`；③ 目录根下存在文件且最近 180 天无修改；④ 目录不在 Denylist。**任一条件无法判定 ⇒ 不列出**。

## 6 隔离区设计（`Quarantine`）

### 6.1 路径校验（`QuarantinePathValidator`）

```csharp
public enum QuarantinePathLevel { Ok, Warn, Reject }
public sealed record QuarantinePathValidation(QuarantinePathLevel Level, string Message, string Detail);
public QuarantinePathValidation Validate(string candidate, long requiredBytes, IVolumeProbe volumes, IFileSystem fs);
```

| 情况 | 结果 |
| ---- | ---- |
| 网络路径（`\\` 开头、映射驱动器）/ 可移动介质 | `Reject`（U 盘拔出即无法还原）/ `Warn` 由 `IVolumeProbe.IsRemovable` 判定 |
| 不可写 / 无法创建子目录 | `Reject` |
| 指向系统目录、Denylist 路径、磁盘根目录 | `Reject`（落地时统一挂在 `<candidate>\SpaceMaid\Quarantine` 下） |
| 隔离区卷 == 源文件卷（都在 C） | `Warn`："放在 C 盘不会真正释放 C 盘空间，建议改到其他盘" |
| 跨卷且目标卷剩余 < 本次待处理体积 | `Reject`（**同卷移动不预检空间**，需求 3.4-2） |

校验必须**在开始执行之前**完成（需求 3.4-2 / 7 章第 7 条），执行中不再询问。

### 6.2 存储布局与映射表

```
<隔离区>\SpaceMaid\Quarantine\
├─ index.json                        批次索引（原子写）
└─ <yyyyMMdd-HHmmss-fff>\
   ├─ map.json                       本批映射表（还原唯一依据）
   └─ payload\<序号>_<原文件名>       实体文件
```

`map.json`（每条 = 一个被移动的文件，字段即需求 3.4-4 要求）：

```json
{
  "schemaVersion": 1,
  "batchId": "20260920-143012-118",
  "createdAt": "2026-09-20T14:30:12.118+08:00",
  "expiresAt": "2026-09-27T14:30:12.118+08:00",
  "quarantineRoot": "D:\\SpaceMaidQuarantine",
  "sameVolumeAsSource": false,
  "entries": [
    {
      "itemId": "l1.user-temp",
      "category": "L1OneClick",
      "originalPath": "C:\\Users\\u\\AppData\\Local\\Temp\\a.tmp",
      "volumeSerial": "1A2B-3C4D",
      "sizeBytes": 1048576,
      "lastWrite": "2026-09-19T10:00:00+08:00",
      "storedAs": "payload\\0001_a.tmp",
      "restored": false
    }
  ]
}
```

写盘顺序（断电安全，需求 3.4-4 / 3.2-6）：
**① 先写 `map.json`（含 `pending=true` 的文件）→ ② 再移动文件 → ③ 全部完成后把 `pending` 置 false 重写**。
崩溃后启动自检：`pending=true` 的条目按"文件已在 payload 且不存在于原位置"补记账，文件状态不明则标 `status=unknown` 并在复核报告中列为**异常项**（需求 3.9-4）。

### 6.3 移动策略

| 场景 | 实现 |
| ---- | ---- |
| 同卷 | `File.Move`（原子重命名，不占额外空间） |
| 跨卷 | 复制 → 校验（长度 + SHA-256 抽样：小于 64MB 全量校验，更大则校验首尾 4MB + 长度）→ 删除源文件；任一步失败保留源文件并记 `未清理成功` |
| 文件被占用 | 跳过 + 记原因 |
| 目录（`DirectoryTree`） | 逐文件处理，不整目录 `Directory.Delete`，避免误删未授权内容 |

### 6.4 还原与释放

- `RestoreBatchAsync(batchId)`：按映射表逐条搬回；目标已存在同名文件/原卷不可用/空间不足 → 逐条报冲突，**不覆盖**（需求 3.4-6）；
- `ReleaseExpiredAsync(now)`：**惰性**——启动与扫描前各调用一次，释放 `expiresAt <= now` 的批次，并顺带清理 `payload` 中无映射的孤儿文件；
- `ClearAllAsync()`：立即清空（需 UI 二次确认 + 文案"不可还原"）。

## 7 特殊项设计（`Execution`）

### 7.1 休眠授权闸门（`HibernateGate`，需求 3.8）

```csharp
public enum HibernateState { Unknown, Enabled, Disabled, NotSupported }
public sealed record GateResult(bool Executed, string Reason, long FreedBytes);

public sealed class HibernateGate
{
    public HibernateState Probe(ICommandRunner runner);                       // powercfg /a
    public Task<GateResult> DisableAsync(bool userAuthorized, ICommandRunner runner, IFileSystem fs, CancellationToken ct);
}
```

- `userAuthorized == false` ⇒ **立即返回 `Executed=false, Reason="未授权关闭休眠，已跳过"`，且绝不调用 `runner`**（单测断言命令执行次数为 0）；
- 授权后：`powercfg /h off` → 返回码非 0 判失败（**不重试、不降级为删文件**）→ 校验 `C:\hiberfil.sys` 不存在 → 释放量 = 关闭前后可用空间差值；
- 界面文案固定包含：`（仅关闭功能，不删文件）` 与 `恢复：powercfg /h on`，并注明"不影响睡眠与关机"。

### 7.2 组件存储清理（`DismComponentCleanup`）

- 命令固定 `dism.exe /Online /Cleanup-Image /StartComponentCleanup`，**代码中不得出现 `/ResetBase`**（单测断言）；
- 命令不可中断：执行期间界面显示"预计十几分钟，请勿关闭"；超时视为失败但不重复执行；
- 输出解析：从 DISM 输出中提取释放量（解析失败则记 0 并标注"释放量未知"）。

### 7.3 回收站（`RecycleBinTargets`，需求 2.5）

- 默认仅 `%SystemDrive%\$Recycle.Bin`；枚举各 SID 子目录，成对处理 `$I*`（元数据，32 字节头 + 原始路径 UTF-16）与 `$R*`（实体文件）；
- 只把 `$R*` 实体文件当 payload 移入隔离区，`$I*` 元数据单独归档（还原时成对写回）；
- 解析 `$I` 失败的文件**跳过并记原因**；
- 其他分区需设置项 `IncludeOtherDriveRecycleBin` 显式开启（默认 false）。

### 7.4 蓝屏转储保留策略（需求 2.2）

`l1.dumps` + `KeepsNewest=true`：候选 = `MEMORY.DMP` 与 `Minidump\*.dmp` 合并按 `LastWrite` 倒序，保留第一条（无论它在哪个目录），其余全部处理；`LiveKernelReports` 全部处理。清单里明确写出"保留：<路径>"一行（便于用户审阅）。

## 8 清单导出与复核（`Reporting`，需求 3.9）

### 8.1 `CleanPlan`（清单与执行之间的唯一凭据）

```csharp
public sealed record CleanPlanItem(string ItemId, CleanCategory Category, string DisplayName, string ActionText,
                                   IReadOnlyList<ScanFile> Files, long TotalBytes, bool DefaultChecked, bool UserChecked);
public sealed record CleanPlan(string PlanId, DateTimeOffset CreatedAt, ScanReport Scan,
                               IReadOnlyList<CleanPlanItem> Items, long QuarantineRequiredBytes);
```

**不变式（D-7）**：`CleanExecutor` 的执行输入只有 `CleanPlan.Items.Files`；执行器不得再自行枚举目录。清单导出与执行之间**没有自动衔接**（需求 3.9-3）。

### 8.2 产物

| 文件 | 内容 |
| ---- | ---- |
| `清单.md` | 分组（L1/L2/L3/回收站）→ 每项：名称、体积、文件数、路径样本、"动作性质"括号、"保留：xxx"（如适用）、未授权/不可用原因；文件超过 50 个时列前 50 + "其余 N 个见 csv" |
| `清单.csv` | 表头固定：`分级,项目Id,项目名,原始路径,体积字节,最后修改,动作,是否可还原,备注`；**每个将被处理的文件一行**（穷尽性由测试断言：csv 行数 == 计划文件数） |
| `复核报告.md` | 已清理（数量/体积/逐条）、未清理与跳过（含原因）、**异常项**（清单中有但状态不明，必须逐条列出）、释放口径说明（同卷未释放/跨卷已释放） |

导出目录：默认 `D:\logs\SpaceMaid\清单\<yyyyMMdd-HHmmss>\`；不可写时回退 `%LocalAppData%\SpaceMaid\reports\`（需求 6 章日志要求 + 健壮性）。

### 9.2 风险标注（需求 5.4 的机器校验点）

`CleanItemDefinition.ActionNote` / `SideEffect` / `RestoreHint` 直接绑定到界面，规则：

- `Risk != Safe` 的名称渲染为 `名称（ActionNote）`，`Foreground={DynamicResource DangerBrush}`；
- L3 项展开时**必须**显示"恢复方式"；ViewModel 单测断言：每个 L3 视图模型项都有非空 `RestoreHint`；
- 默认勾选状态每次重新扫描后重置为 `DefaultChecked`（不读上次状态）。

### 9.3 体积文案口径（D-6）

`VolumeTextFormatter`（Core，可单测）：
- 跨卷隔离：`已释放 X GB`
- 同卷隔离：`已移入隔离区 X GB（保留期结束或清空后释放）`
- 汇总永远同时给两个数字：`本次可处理` / `实际释放`。

| 层 | 手段 | 覆盖重点 |

## 13 风险与取舍记录

| 风险 | 取舍 |
| ---- | ---- |
| 全量进隔离区导致 C 盘不立即释放 | 已按需求保留该行为；用默认建议 + 校验提醒 + 双口径文案缓解 |
| 隔离区长期增长 | 7 天惰性释放 + 设置页显示占用 + "立即清空" |
| DISM 与 卸载残留判定不可靠 | 前者只跑官方命令且不提供 /ResetBase；后者采用 5.4 的"判定不确定就不列出" |
| 大文件/重复文件可能几十 GB | 只列清单、默认不勾、用户逐条决定（需求 2.4） |
| 工具以管理员运行，破坏力大 | I-1…I-6 全部由测试守住；禁止清单硬编码；无永久删除路径 |
| 实机删除测试有风险 | 只在自建临时目录做自动化；系统目录的删除永远由用户按 3.9 流程在真机执行 |
