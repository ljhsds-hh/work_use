复现命令（在仓库根执行）：

```powershell
$src = 'SpaceMaid/Code/tests'
foreach ($d in @('SpaceMaid.Core.Tests','SpaceMaid.App.Tests')) {
  $sub = 0
  Get-ChildItem -Path (Join-Path $src $d) -Recurse -Filter *.cs |
    Where-Object { $_.FullName -notmatch '\\(obj|bin)\\' } |
    ForEach-Object {
      $t = Get-Content -LiteralPath $_.FullName -Raw
      $sub += ([regex]::Matches($t,'\[Fact\]')).Count + ([regex]::Matches($t,'\[InlineData')).Count
    }
  "$d = $sub"
}
```

### 1.4 关于"尚未实机执行真实清理"

**必须明确记录的边界**：

> **本项目尚未在真机上执行过对真实系统目录的清理动作。**

依据需求 3.9 约定的验收协作流程：**工具只出清单不删，删除动作由用户在真机执行**。因此：

- 自动化测试**不触碰任何真实系统目录**（`C:\Windows\*`、真实用户 `%TEMP%` 等一律不碰）。所有 IO 测试的根目录都在 `%TEMP%\spacemaid-tests-<guid>` 下自建、`finally` 中删除（见 `Abstractions/TempRoot.cs`）；
- 涉及系统命令的测试（`powercfg`、`dism`）一律用假 `ICommandRunner` 验证**命令参数与调用次数**，**不真的执行命令**；因此"实机执行 `powercfg /h off` 后 `hiberfil.sys` 消失"这一条只有设计证据与单测证据，**没有实机证据**；
- 涉及跨卷的路径用假 `IVolumeProbe`（把两个临时目录标成不同卷）验证，**不依赖真机多分区**；
- 静态检索测试读的是 `Code/src/SpaceMaid.Core/**/*.cs` 源码文本，属于源码级证据而不是行为证据。

因此下表中凡涉及"在测试机上由用户执行清理 + 重启后系统正常"的条目，状态一律为**部分满足（待实机验收）**，不写成"已满足"。

### 3.1 重置基线断言的收紧（2026-09-20 已修复）

曾发现一处**断言与意图之间的缺口**，现已修复并记录在此以备追溯：

- **原状**：`Core_should_not_use_component_store_reset_base` 断言的是**带斜杠**的 `/ResetBase`，而 `CleanItemCatalog` 中 `l3.component-store` 的后果说明文案含有**不带斜杠**的 `ResetBase` 字样。该用例当时**通过**，但并没有真正拦住这句文案——属于"看着通过、拦不住真问题"。
- **风险**：这种口径下，断言只能发现"把开关当成 `/ResetBase` 参数写进命令"，拦不住"以别的写法把开关拼进命令"。
- **修复（提交 `a8b1eac` fix: 收紧重置基线断言并修正递归通配规则的授权口径）**：
  1. 断言收紧为**裸字串 `ResetBase`**（`StringComparison.OrdinalIgnoreCase`）在整个 Core 源码中都不出现；
  2. `l3.component-store` 的产品文案改为「本工具不提供「重置基线」选项（启用它会让你无法卸载任何已安装的更新）」，不再出现英文开关名。
- **当前状态**：Core 源码中已无 `ResetBase` 字样，收紧后的断言可通过。

**后续约束**：如果确实需要重新在文案里写出这个开关名，**必须同时放宽这条断言**并在 `Docs/评审记录.md` 说明理由；但要先评估代价——写出开关名只对排障有用，而漏掉一次命令参数会让用户再也无法卸载已安装的更新。

> 全局约束里的"**不得实现 `/ResetBase`**"指的是**实现**（命令参数），`DismComponentCleanup.Arguments` 常量里确实没有它，参数也不接受外部拼装。

## 五、测试纪律（对后续改动的约束）

以下约束来自 `Docs/设计文档.md` 第 11 章与 `Docs/实施计划.md` 的 Global Constraints，任何新增测试都必须遵守：

1. **不得触碰真实系统目录**：所有 IO 测试的根目录必须在 `%TEMP%\spacemaid-tests-<guid>` 下，并在 `finally` 中删除；
2. **不得真的执行系统命令**：`powercfg` / `dism` 只能通过假 `ICommandRunner` 验证参数与调用次数；
3. **跨卷场景用假 `IVolumeProbe`**（把两个临时目录标成不同卷），不依赖真机多分区；
4. **新增删除调用点**必须同时更新 `StaticSafetyTests.DeleteAllowlist` 并写明理由，否则静态检索测试变红；
5. **新增清理项**必须过 `CatalogValidator` 全部规则，否则 `Catalog_should_have_no_violations` 变红；
6. **不得为让测试通过而放宽安全断言**（尤其是 `Denylist` / `SafetyGate` / `StaticSafetyTests` 三处）。

## 六、结论

- **内核侧（`SpaceMaid.Core`）**：安全底座、清单闭集、扫描、隔离区（含断电自检）、执行器、清单与复核、特殊项（休眠闸门 / DISM / 回收站）、设置与日志均已有对应测试，需求第 7 章中**第 4、6、10、12、13、15 条**可判定为满足，**第 1、2、5、7、8、9、11、14 条**部分满足（缺口集中在界面交付与实机验收），**第 3 条**待实测；
- **界面侧（`SpaceMaid.App`）**：尚未交付，相关验收条目（第 1、5、8、11、14 条的界面部分）无法判定；
- **实机验收**：按需求 3.9，真实清理动作**尚未在真机执行过**，这一部分只能由用户完成；本报告不把这部分写成"已通过"。
