## 1 总体概述
### 1.1 产品定位
本工具面向 Windows 桌面（以 Win11 为主要目标系统），用于**定时提醒用户完成待办任务**。用户预先设置若干任务及循环规则，软件到点弹出全屏暗化遮罩与居中提醒卡片；针对办公场景中"到点前关机 / 重启导致提醒错过"的情况，提供两级保障：
1. **关机前拦截提醒**：系统发起关机（或重启、注销）时，若存在关机后将错过的未完成任务，软件抢先弹出提醒，给用户一次确认机会；
2. **开机后立即补提醒**：若任务确已错过（软件未运行期间到期），下次开机软件自启后立即补提醒。

软件主界面保持简洁克制，仅做"任务管理"一件事；提醒环节做到醒目、必达。**本工具不提供声音提醒，不提供统计报表、日历视图等扩展功能，核心功能只有一个：提醒我有任务。**

### 1.2 核心约束前置强调
1. 提醒必须"必达"：任何任务实例（见 1.3 术语）不允许无声消失——要么按时提醒、要么关机前拦截、要么开机后补提醒，三者必居其一；
2. 提醒弹出时必须**置顶于所有窗口之上**（Topmost），确保用户看到；
3. 提醒环节**不使用任何声音**（不播放提示音、不调用系统提示音）；
4. 主界面功能保持克制：只做任务的增、删、改、查、启用/停用与提醒触发，不添加任务以外的主功能；
5. 所有任务数据本地持久化，软件退出、重启、关机后数据不丢失；
6. 软件默认随系统开机自启动，并配套**进程守护机制**（详见第 7 章）：进程被误退、误杀后自动拉起，此为"错过补提醒"成立的前提；
7. 软件全程**单实例运行**：无论开机启动、守护拉起还是用户手动双击，同一时刻全系统只允许存在一个 QuietRemind 进程，重复启动时新实例自动退出并唤起已有实例主界面；
8. **轻量原则（最小而不失真）**：本工具功能单一，必须始终保持轻量本色，严禁演变为"毒瘤软件"：
   - 常驻后台资源占用保持低水平：稳定空载内存参考目标 ≤ 100MB，空闲时 CPU 占用趋近于 0（仅允许秒级低频轮询，禁止高频空转扫描、禁止常驻忙等线程）；
   - 除第 7 章进程守护计划任务外，不注册任何其他系统服务/自启项，不创建常驻子进程，不后台联网，无任何推广弹窗、广告与数据采集行为；
   - 发布产物体积保持轻量，发布模式以体积优先选择；程序本体、数据文件与日志的磁盘总占用保持小体量水平；
   - 轻量不以牺牲功能为前提：本条所称"不失真"，指 1.2 第 1 条"提醒必达"等核心约束必须完整实现，提醒链路一项不许缩水。

### 1.3 术语定义
1. **任务（Task）**：用户设置的一条提醒规则，包含任务内容、提醒时刻、循环规则、启用状态。任务本身可长期存在，按循环规则反复产生提醒；
2. **任务实例（Task Occurrence）**：某任务按循环规则在某个具体日期/时刻产生的一次"计划触发"，是提醒与收尾的基本单位。每个任务实例拥有独立状态；
3. **循环规则（Recurrence）**：任务实例的生成方式，见第 2 章；
4. **收尾（Settle）**：用户对某次提醒做出的处理动作，即【完成】/【稍后再提醒】/【跳过】三者之一。收尾完成后该任务实例进入终态；
5. **错过（Missed）**：某任务实例的计划时刻已过，但实例尚未进入终态（未完成、未跳过），且当时软件未在运行（或系统处于睡眠状态）——该实例判定为错过。

## 2 任务管理
### 2.1 任务字段
| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| 任务内容 | 是 | 一句话描述要做的事，如"16:50 交日报"；界面主展示项 |
| 提醒时刻 | 是 | 具体到时:分（如 16:50）；单次任务还需指定日期 |
| 循环规则 | 是 | 见 2.2，默认"每天" |
| 启用状态 | 是 | 启用 / 停用；停用任务不生成任何任务实例、不参与提醒 |

### 2.2 循环规则
支持以下四种基础规则（提醒软件通用类型，不额外扩展）：
1. **单次**：仅在指定的某个日期、时刻提醒一次；触发并收尾后（无论完成还是跳过），任务自动转为已结束状态并停止产生实例（任务保留在列表中供查看，可手动删除）；
2. **每天**：每日固定时刻提醒；
3. **每周**：每周的指定星期几（可多选，如勾选周一~周五即等效工作日提醒）固定时刻提醒；
4. **每月**：每月指定日期（1~31）固定时刻提醒；若当月无该日期（如 31 日遇 2 月），取当月最后一天触发。

### 2.3 任务操作
1. 新增任务：主界面填写字段后保存，即时生效（若新增任务的计划时刻恰好已过当日时刻，则从下一个循环周期开始生成实例，不追溯当天已过时刻）；
2. 编辑任务：可修改全部字段，仅影响尚未触发的任务实例，不改变已收尾实例的历史状态；
3. 删除任务：弹出 HandyControl 二次确认弹窗，确认后删除；删除不追溯、不清除已产生的历史实例记录；
4. 启用/停用：列表内开关直接切换，停用后该任务不再生成新实例，已生成未收尾实例不再触发提醒。

## 3 到点提醒
### 3.1 触发机制
1. 软件后台以秒级轮询扫描任务实例，计划时刻到达即触发提醒；
2. 系统时钟校准（如 NTP 同步导致时间跳变）、时区变化后，轮询按当前系统时间重新扫描，不出现漏触发或重复触发。

### 3.2 提醒界面
1. 提醒以**全屏暗化遮罩 + 屏幕居中提醒卡片**呈现：无边框、置顶（Topmost），背景半透明暗化遮罩阻断对桌面其他内容的注意力；居中卡片为带阴影圆角卡片（宽约 520px，左侧品牌色状态条），样式醒目（2026-09-19 按用户反馈定稿：全屏遮罩 + 模板卡片样式居中）；
2. 卡片内逐条展示任务：任务标题 + 循环规则标签，同时到期多个任务时逐条堆叠展示（见 3.4）；已错过的实例条目带"已错过"红色徽标及原计划时刻；
3. 醒目动效：卡片采用浮入（上移 + 淡入）动效增强注意，**不做花瓣、开花等具象装饰动画**；
4. **全程无声音**；
5. 遮罩出现后，用户必须对该卡片内每条任务条目做出收尾处理（完成 / 稍后再提醒 / 跳过三者之一），遮罩方可关闭（无关闭按钮，ESC / Alt+F4 均不可关闭）。

### 3.3 收尾交互
每条任务实例提供三个收尾按钮：
| 按钮 | 行为 |
| ---- | ---- |
| 【完成】 | 该实例标记为"已完成"，终态 |
| 【稍后再提醒】 | 弹出间隔选择（5 / 10 / 30 分钟），选择后该实例推迟所选时长再次触发提醒；推迟期间实例状态回到"待提醒" |
| 【跳过】 | 该实例标记为"已跳过"，本次不再提醒，终态 |

说明：进入"稍后再提醒"推迟期后，若在再次触发前发生关机/软件退出，该实例按"错过"处理（见第 5 章）。

### 3.4 多任务同时到期
1. 同一时刻（同一轮询周期内）到期多个任务实例时，合并在**同一个**提醒窗口中列表展示，逐条独立收尾，不弹出多个窗口；
2. 全部条目收尾完毕后，提醒窗口自动关闭；
3. "稍后再提醒"仅推迟当前操作的那一条，其余条目继续等待收尾。

## 4 关机前拦截提醒
### 4.1 触发条件
系统发起**关机、重启或注销**时，软件检测当前存在满足以下全部条件的任务实例：
1. 计划时刻在本次关机后将错过（计划时刻未到，或已到但未收尾）；
2. 所属任务为启用状态；
3. 实例尚未进入终态（未完成、未跳过）。

即：**今天还欠着、且关机后就提醒不到的任务**，必须触发拦截。

### 4.2 拦截行为
1. 拦截提醒以系统对话框形式呈现（可复用提醒浮层或模态弹窗，视觉醒目），文案明确告知：关机后以下任务将被错过，逐条列出任务内容与计划时刻；
2. 提供【取消关机】与【仍要关机】两个选择：
   - 【取消关机】：中止本次系统关机流程，用户返回桌面处理任务（处理完成后可自行关机，届时若任务已收尾则不再拦截）;
   - 【仍要关机】：放行关机流程，软件不做任何阻塞；这些任务实例保持"待提醒"状态，等待下次开机补提醒；
3. 拦截提醒**不使用声音**；
4. 若关机时不存在满足条件的任务实例，软件不得拦截、不得弹窗，静默放行关机。

### 4.3 硬性边界
1. 已全部收尾（完成/跳过）或当日无待提醒实例时，禁止触发拦截弹窗——不允许在任何情况下无理由拖延关机；
2. 用户点击【仍要关机】后，系统关机流程必须在数秒内放行，不得反复拦截。

## 5 错过判定与开机补提醒
### 5.1 错过判定
1. 软件在以下三个时机执行"错过扫描"：**软件启动时**、**系统从睡眠/休眠唤醒时**、**每次轮询周期**；
2. 扫描规则：任务实例计划时刻已过，且实例尚未进入终态（未完成、未跳过）——判定为**错过**；其中：
   - 软件本次运行期间正常到点的实例，一律由 3.1 即时触发正常提醒，**不判为错过**（"已错过"徽标仅出现在补提醒场景）；
   - 时钟校准跳变（3.1 第 2 条）导致计划时刻被整体跳过的实例，由轮询扫描兜底判为错过并立即补提醒；
3. 被判定为错过的实例，由"待提醒"转为"已错过"状态，等待补提醒展示；
4. **提醒弹出本身不改变实例状态**：实例状态仅由收尾动作变更（完成/跳过为终态，稍后再提醒回到待提醒）。即使提醒窗口已弹出，只要未收尾，实例仍按上述规则参与错过扫描——保障"提醒弹出后软件被强杀/关机"的场景在下次启动时依然被补提醒覆盖，不存在状态死角。

### 5.2 开机补提醒
1. 软件随系统开机自启动（计划任务方式，见第 7 章；默认开启，设置中可关闭）；
2. 启动后执行错过扫描，若存在"已错过"实例，**立即弹出**与 3.2 同规格的提醒浮层，实例条目上醒目标注"已错过"徽标及原计划时刻；
3. 补提醒的收尾交互与 3.3 完全一致（完成 / 稍后再提醒 / 跳过）；错过的实例选择"稍后再提醒"时，按所选间隔正常推迟触发；
4. 用户手动启动软件时，同样执行错过扫描并补提醒；
5. 若启动扫描无错过实例，软件静默进入托盘，不弹出任何窗口打扰用户。

## 6 主界面、托盘与设置
### 6.1 主界面
1. 主界面仅包含两大区域：
   - **任务列表**：逐条展示任务内容、循环规则、提醒时刻、启用开关；醒目区分今日待提醒条目；支持新增、编辑、删除；
   - **设置区**：开机自启动与进程守护开关（见 6.3）、稍后提醒间隔等少量配置项；
2. 整体布局简洁克制，遵循 HandyControl 默认视觉风格，不添加多余装饰。

### 6.2 托盘常驻
1. 软件启动后常驻系统托盘；点击关闭主界面窗口 = 最小化到托盘，**不退出进程**（否则提醒与错过检测将失效）；
2. 托盘图标支持右键菜单：【打开主界面】、【立即退出】；
3. 点击【立即退出】弹出二次确认，确认文案需向用户明示：**退出后进程守护不再拉起，本次开机周期内到点提醒与错过检测均不生效，重启电脑后自动恢复**；确认后写入"用户主动退出"标记（见 7.4）再退出进程。
4. 托盘图标为 HandyControl 未覆盖的控件，允许采用 WPF 原生 / 成熟第三方方案实现。

### 6.3 设置项
| 设置项 | 默认值 | 说明 |
| ---- | ---- | ---- |
| 开机自启动与进程守护 | 开启 | 通过注册 Windows 计划任务实现（见第 7 章）；关闭即注销计划任务，不再自启、不再守护 |
| 稍后提醒间隔 | 5 / 10 / 30 分钟 | 提醒窗口【稍后再提醒】提供的候选间隔 |

## 7 进程守护机制
> 背景说明：Windows 服务运行于 Session 0，无法向用户桌面弹出任何窗口（会话隔离），无法承担全屏提醒、关机拦截职责；本工具不采用服务形态，采用 **单进程 + 计划任务守护** 方案实现"不怕误退、不漏提醒"。

### 7.1 计划任务注册
1. 软件首次运行（或设置开启"开机自启动与进程守护"）时，以**当前用户**身份注册一个 Windows 计划任务，任务名固定为 `QuietRemind`；
2. 计划任务包含两类触发器：
   - **登录触发**：用户登录系统时启动软件（实现开机自启动）；
   - **守护触发**：每 5 分钟重复触发一次，无限期持续；
3. 计划任务动作统一为启动本程序 exe，并勾选"如果此任务已在运行，则不启动新实例"；
4. 设置中关闭该开关时，注销上述计划任务，此后既不自启也不守护。

### 7.2 守护拉起逻辑
1. 守护触发时，计划任务启动一个新的程序实例；新实例启动后检测系统内是否已有 QuietRemind 进程在运行：
   - 已有 → 新实例立即静默退出（配合 1.2 单实例约束，形成"检测不在才拉起"的守护效果）；
   - 没有且无"用户主动退出"标记（见 7.4） → 新实例作为正式实例静默启动（进入托盘，执行错过扫描）——即进程被误退、误杀后，最迟 5 分钟内自动恢复；
   - 没有但存在"用户主动退出"标记 → 本轮不拉起，静默退出；
2. 守护拉起全程无窗口、无提示，不打扰用户。

### 7.3 单实例互斥
1. 程序使用系统级命名互斥体（Mutex）保证单实例，互斥体在进程存活期间持有，进程退出即释放；
2. 重复启动（用户手动双击、守护重复拉起）时，新实例检测到互斥体已被持有即静默退出；若新实例由用户手动启动，则先通知已有实例弹出主界面，再自行退出。

### 7.4 用户主动退出标记
1. 用户通过托盘【立即退出】二次确认后，软件在数据目录写入主动退出标记文件（含时间戳），随后退出进程；
2. 标记文件存在期间，守护触发不再拉起进程——保证用户"退出"的决定在一个开机周期内有效；
3. **登录触发忽略标记**：下次开机登录时计划任务照常启动软件，启动成功后自动清除标记——每个开机周期开始时守护状态重置，避免用户忘记重新打开软件导致整天无提醒。

## 8 数据持久化
1. 任务定义、实例状态（待提醒 / 已错过 / 已完成 / 已跳过）、设置项、用户主动退出标记全部持久化到本地 JSON 文件，存储于 `%AppData%\QuietRemind\` 目录；
2. 任何状态变更（新增/编辑/删除任务、收尾、错过判定、主动退出标记写入与清除）实时落盘，确保断电、强制关机后重启数据不丢失；
3. 历史实例记录保留供"欠账"判定，任务删除后其关联实例一并停止参与提醒。

## 9 界面与交互通用要求
1. UI 整体风格依托 HandyControl 组件库实现，布局简洁适配办公使用场景；**一切以 HandyControl 控件为核心构建界面**：凡 HandyControl 已提供的控件（窗口、按钮、输入框、日期/时间选择器、开关、弹窗、列表、提示等），一律优先使用 HandyControl 实现；仅当 HandyControl 未提供必要控件时，才退而使用 WPF 原生控件；
2. 提醒浮层属于特殊形态窗口（无边框置顶浮层），允许以 WPF 原生窗口能力实现，内部控件仍遵循 HandyControl-first 原则（自绘开关、标签等 HC 未提供的元素除外）；
3. 软件异常（数据读写失败、扫描异常等）必须完整捕获，写入日志并以界面友好提示；任何异常不得导致提醒机制静默失效；
4. 界面文案全部使用简体中文。

## 10 全局持久化日志
1. 程序全生命周期统一写入本地日志文件：启动/退出、守护拉起结果（拉起/跳过及原因）、任务增删改、实例状态流转（待提醒/错过/完成/跳过）、提醒触发、关机拦截交互结果、睡眠唤醒扫描结果、所有捕获异常等全量信息；
2. 存储位置：`D:\logs\QuietRemind\` 目录下，按日期分文件；
3. 日志自动滚动清理：仅保留最近 30 天，过期日志自动删除，严禁日志无限膨胀占用磁盘（呼应 1.2 轻量原则）；
4. 作用：故障排查、提醒链路回溯（某任务为什么没提醒到，必须可从日志还原全过程）。
