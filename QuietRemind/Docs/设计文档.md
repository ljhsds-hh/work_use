# QuietRemind 任务提醒工具 设计文档

> 依据 [需求.md](需求.md) 设计，本文档为开发基线：定义架构分层、领域模型、核心状态机、启动编排、模块契约、持久化格式与测试策略。

## 1 架构总览

| 层 | 目录 | 职责 | UI 依赖 |
| --- | --- | --- | --- |
| 领域模型 | `Models/` | Task / Occurrence / 枚举 / AppSettings | 无 |
| 服务层 | `Services/` | 实例规划、提醒引擎、错过扫描、关机拦截判定、计划任务守护、JSON 存储、日志、时钟、睡眠监听 | 无（可单元测试） |
| 视图模型 | `ViewModels/` | 主界面、编辑、收尾命令 | 仅基础类型 |
| 视图 | `Views/` | 主窗口 / 编辑窗 / 全屏提醒窗 / 关机拦截窗 | HandyControl |
| 基础设施 | `Helpers/` | RelayCommand、ViewModelBase、转换器、单实例 | 无 |
| 编排 | `App.xaml.cs` | 启动序列、全局异常兜底、系统事件挂接 | WPF |

**关键原则**：服务层零 UI 依赖——全部核心逻辑（生成、触发、错过、拦截判定、存储）不引用 WPF 类型，由 `IClock` 注入时间，可在测试工程中完整单测。UI 仅做展示与转发。

## 2 领域模型

### 2.1 ReminderTask（任务）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| Id | Guid | 主键 |
| Content | string | 任务内容（1~200 字） |
| Time | TimeSpan | 提醒时刻 时:分 |
| RecurrenceType | enum | Once / Daily / Weekly / Monthly |
| SingleDate | DateOnly? | 仅 Once：指定日期 |
| StartDate | DateOnly? | 循环开始日期（仅 Daily/Weekly/Monthly；null = 从今天起，晚于今天则从该日起生成） |
| WeekDays | DayOfWeek[] | 仅 Weekly：勾选的星期 |
| MonthDay | int | 仅 Monthly：1~31，超限取当月月末 |
| Enabled | bool | 启用/停用 |
| CreatedAt / UpdatedAt | DateTime | 审计 |

### 2.2 Occurrence（任务实例）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| Id | Guid | 主键 |
| TaskId | Guid | 所属任务 |
| TriggerAt | DateTime | 当前计划触发时刻（snooze 时被更新） |
| OriginalTriggerAt | DateTime | 初始计划时刻（历史展示用，不可变） |
| State | enum | Pending / Missed / Completed / Skipped |
| ReminderShownAt | DateTime? | 本次进程内首次弹窗时刻（幂等标识，见 3.2） |
| SettledAt | DateTime? | 收尾时刻 |

**状态流转（终态不可逆）**：

```
              ┌───────────────────────────────────────────────┐
              │  snooze: TriggerAt=now+间隔, 回 Pending         │
              ▼                                               │
 Pending ──到点触发──► (弹窗, 状态不变, runtimeShown 标记) ──收尾──► Completed
    │                                                         └──────► Skipped
    └──错过扫描(启动/唤醒/轮询)──► Missed ──补提醒弹窗──► 收尾 ──► 终态
```

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| GuardEnabled | true | 开机自启动与进程守护（计划任务注册/注销） |
| SnoozeMinutes | [5, 10, 30] | 稍后再提醒候选间隔（分钟，各 1~120，可配置） |

## 3 核心状态机（需求 3 / 5 章落地）

### 3.1 引擎内存态 `runtimeShown: HashSet<Guid>`

进程内"本次运行已弹过提醒"的实例集合。**仅存内存**，进程退出即清空——这是"强杀/关机后重启仍能补提醒"（需求 5.1.4）成立的机制基础。

### 3.2 三条判定规则（引擎每次轮询按序执行）

1. **触发判定**（需求 3.1）：`State==Pending && TriggerAt<=now && !runtimeShown.Contains(Id)` → 弹全屏提醒窗，`runtimeShown.Add`，`ReminderShownAt=now`（**不改 State**，收尾才改——需求 5.1.4）
2. **错过扫描**（需求 5.1，启动/唤醒/每轮询同一条规则）：`State==Pending && TriggerAt<=now && !runtimeShown.Contains(Id)` → `State=Missed`，补提醒弹窗（"已错过"徽标），`runtimeShown.Add`
3. **收尾**（需求 3.3）：【完成】→ `State=Completed`；【跳过】→ `State=Skipped`；【稍后再提醒】→ `TriggerAt=now+所选间隔`、`State=Pending`、`runtimeShown.Remove`、`ReminderShownAt=null`

### 3.3 规则自洽性论证

| 场景 | 结果 |
| --- | --- |
| 到点正常触发后同轮询扫描 | 触发先执行并加入 runtimeShown → 扫描豁免，不误判"已错过"（5.1.2 第一条） |
| 提醒窗未收尾、进程被强杀 | runtimeShown 随进程消失 → 下次启动扫描：已过点未终态 → 判错过补提醒（5.1.4） |
| 时钟跳变整体跳过计划时刻 | 无 runtimeShown 保护 → 轮询兜底判错过补提醒（5.1.2 第二条） |
| 睡眠期间到点 | 唤醒扫描：未弹过 → 判错过补提醒 |
| snooze 推迟中关机 | TriggerAt 已更新为未来 → 关机拦截按"今天欠账"拦截；未拦到则下次开机扫描判错过（3.3 说明） |
| 提醒窗挂起期间轮询 | 已弹（runtimeShown）→ 豁免，状态不乱 |

## 4 模块设计

### 4.1 IClock / SystemClock / FakeClock

```csharp
public interface IClock { DateTime Now { get; } }
```
生产用 `SystemClock`，测试注入 `FakeClock`（可拨动）。

### 4.2 OccurrencePlanner（实例规划器）

- `EnsureUpTo(occurrences, tasks, horizonDays)`：为每个**启用**任务补齐 `[生效起始日, 生效起始日+7天)` 内缺失实例，返回新增数；按任务 Id 已存在实例去重；生效起始日 = StartDate 晚于今天时取 StartDate，否则取今天
- 生成规则：Once 仅 SingleDate 一天；Daily 每天；Weekly 勾选星期；Monthly 每月 MonthDay 日（`DateTime.DaysInMonth` 取月末）
- **当天已过时刻不追溯**（需求 2.3.1）：生成实例时 `at <= now` 跳过
- **编辑任务重建**：`RebuildFuture(ReminderTask)` 删除该任务全部未收尾实例（Pending/Missed，含已触发、已错过、snooze 推迟中的），按新规则重新生成并**立即生效**——编辑后当天按新时刻触发（需求 2.3.2，2026-09-19 用户澄清）；已收尾实例保留不动；去重时仅未收尾实例占位（同日已收尾不阻塞新实例生成）
- 停用任务：引擎过滤（不生成、不触发、不拦截），实例保留
- **删除任务**：实例**全部保留**（需求 2.3.3"不清除已产生的历史实例记录"、8.3"保留供欠账判定"），引擎/拦截判定按"任务列表中不存在该任务"自然停止处理其全部实例
- Once 任务：最后一个实例收尾后任务转"已结束"（界面展示，`IsEnded` 计算属性：Once 且无 Pending/Missed 实例）

### 4.3 ReminderEngine（提醒引擎）

- `Poll(occurrences, tasks)`：每次轮询按序执行——常规轮询先**错过扫描**（cutoff=上次轮询时刻）再**触发判定**（窗口 `(上次轮询, 当前]`）；首轮 `_lastPoll` 初始化为 `now-2s`（启动扫描已处理过点实例，此处仅打开常规触发窗口）；时钟向前大跳（间隔 >10s 且非睡眠）转**全量错过扫描**兜底；末尾推进 `_lastPoll`
- `ScanMissed(occurrences, tasks, now, cutoff)`：错过扫描（启动 / 睡眠唤醒 / 时钟跳变后显式调用），cutoff 之前到点且未弹过的 Pending 实例判错过并补提醒
- 触发与扫描均过滤停用任务实例（需求 2.3.4）；到期多条合并一次事件（需求 3.4）
- 收尾 `Settle(occurrence, action, interval?)`：完成/跳过终态；稍后再提醒推迟回待提醒，实时落盘由调用方执行
- 秒级轮询：WPF `DispatcherTimer` 1s 间隔（轻量：仅做时间比较与内存集检查，无 IO、无高频空转）

### 4.4 ShutdownIntercept（关机拦截判定）

`GetOwedOccurrences(now, tasks, occurrences)` 欠账判定（需求 4.1）：

```
Task.Enabled && State==Pending && TriggerAt.Date == today
```

（Pending 且今天 → 无论时刻已过未过，关机后都提醒不到 → 拦截。明天任务不拦——"今天还欠着"。）

### 4.5 TaskSchedulerGuard（计划任务守护，需求 7 章）

基于 `Microsoft.Win32.TaskScheduler`（包 ID：`TaskScheduler`）：

- `EnsureRegistered()`：任务名 `QuietRemind`；**LogonTrigger 优先 + TimeTrigger 每 5 分钟重复**；`MultipleInstances.IgnoreNew`；`LogonType.InteractiveToken`（当前用户免密，需显式传 userId）；已存在且动作路径/守护触发器配置一致则幂等跳过
- **降级机制**：部分环境（受限令牌）拒绝创建 LogonTrigger → 自动降级为**仅守护触发**并记日志；开机自启语义由进程内 `IsRecentBootStartup()`（系统启动 2 分钟内的守护触发按登录语义处理）等价保障
- TimeTrigger 起点 = 注册时刻 + 5 分钟（避免固定次日起点造成注册当天近 24 小时守护空窗）
- `Unregister()`：注销任务（设置关闭时）
- 返回操作结果（成功/失败原因）供界面提示

### 4.6 SingleInstance（单实例 + 唤醒）

- 命名 Mutex：优先 `Global\QuietRemind`（需求 1.2.7 全系统单实例），受限环境创建失败自动回退 `Local\`（会话级）
- 命名 EventWaitHandle `QuietRemind_ShowMain`（同样 Global 优先、Local 回退）：手动启动的重复实例 Set() 唤醒已有实例显示主窗口
- 已有实例**并入 1s 主轮询**消费信号（`TryConsumeShowMainSignal`，无常驻后台线程）

### 4.7 JsonStore（持久化）

- 目录 `%AppData%\QuietRemind\`，文件 `tasks.json` / `occurrences.json` / `settings.json`；**退出标记 `exit.marker` 存放于日志目录 `D:\logs\QuietRemind\`**——部分环境的计划任务守护进程对 `%AppData%` 新写入文件存在视图隔离，而日志目录在用户会话进程与守护进程间视图一致（实测验证）
- System.Text.Json 序列化（枚举转字符串）；**原子写**：写临时文件 → `File.Move(overwrite)`（同目录改名即原子替换），断电/强杀不损坏
- 损坏恢复：解析失败 → 日志 + 备份损坏文件（`.corrupt-时间戳`）→ 以空数据启动并提示用户
- 任何状态变更实时落盘（需求 8.2）：任务增删改、收尾、**错过判定**、标记写入与清除

### 4.8 LogService（全局日志，需求 10 章）

- 路径 `D:\logs\QuietRemind\yyyy-MM-dd.log`（目录不存在自动创建）
- 行格式：`[时间] [级别] 消息`；级别 Info / Warn / Error
- 全生命周期记录：启动/退出、守护拉起结果、任务增删改、实例状态流转、提醒触发、拦截交互结果、睡眠唤醒扫描、异常（含堆栈）
- 滚动清理：每次启动 + 每日首次写入时删除 30 天前文件；写失败静默（吞异常，不拖垮主流程）

### 4.9 SleepWatcher（睡眠唤醒）

`SystemEvents.PowerModeChanged` → `Resume/Suspend` 事件 → 触发引擎立即轮询 + 错过扫描，并记日志。

## 5 启动编排（App.xaml.cs）

```
Main 入口（无 StartupUri，手工编排）
├─ 解析参数：--scheduled（计划任务启动）/ 无（手动）；进程内以 IsRecentBootStartup
│   （系统启动 2 分钟内）将计划任务启动进一步区分为"登录语义"与"守护语义"
├─ 单实例 Mutex 获取（Global 优先，Local 回退）
│   ├─ 失败 → --scheduled: 静默退出
│   │       → 手动: 发 ShowMain 信号 → 退出
│   └─ 成功 → 读取 exit.marker（存于日志目录，见 4.7）
│       ├─ 存在且守护语义 → 静默退出（标记保留，本轮不拉起，需求 7.2）
│       └─ 存在且登录/手动语义 → 清除标记（登录周期重置，需求 7.4.3）
├─ 初始化日志 → 加载数据（JsonStore）
├─ GuardEnabled → TaskSchedulerGuard.EnsureRegistered()（失败日志+提示，不阻断启动）
├─ 挂接：SessionEnding / PowerModeChanged / 全局异常
├─ 实例补齐（EnsureUpTo）→ 落盘 → 错过扫描（有错过 → 落盘 + 补提醒窗；无 → 静默）
├─ 1s 轮询：补齐实例 → 错过扫描/触发判定 → 消费单实例唤醒信号
└─ --scheduled → 静默进托盘；手动 → 显示主窗口
```

## 6 关机拦截交互（需求 4 章）

1. 系统发起关机/重启/注销 → WPF `Application.SessionEnding` 触发（UI 线程）
2. `GetOwedOccurrences` 为空 → 立即返回（静默放行，不设 Cancel）
3. 非空 → **在 SessionEnding 处理器内同步 `ShowDialog` 拦截窗**：模态消息泵运行期间，系统等待本进程回复 WM_QUERYENDSESSION，用户操作窗口不受影响
4. 拦截窗逐条列出任务内容与计划时刻，提供：
   - 【取消关机】→ `e.Cancel = true` → 系统撤销关机流程
   - 【仍要关机】→ 不设 Cancel → 系统按原始意图（关机/重启/注销）继续 → 实例保持 Pending 等待下次开机补提醒
5. 无 ExitWindowsEx 重发 → 天然避免"重启 vs 关机无法区分"与"反复拦截"问题（需求 4.3.2）
6. 全程无声音；结果记日志

## 7 提醒窗口行为（需求 3.2 / 5.2；2026-09-19 定稿：全屏暗化遮罩 + 模板卡片样式居中）

- **全屏遮罩 + 居中卡片**：无边框 Topmost 最大化窗口（WindowChrome，不盖任务栏）；遮罩分层 = 底色 #101018 → 自定义背景图（UniformToFill 铺满 + 可选 BlurEffect，2026-09-19 用户追加）→ 暗化层（黑，Opacity = 设置的暗化百分比 0~90%）；居中白卡 520px、圆角 10、投影（BlurRadius 36 / Opacity 0.35）、左侧 5px 品牌状态条（用户模板样式）
- 背景图在上传时拷贝至数据目录（`reminder-bg.*`）统一管理，失效（删除/损坏）时自动回退深色底不影响提醒
- 卡片结构：头部（品牌 logo / "QuietRemind · 到期提醒" / ⏰ 最早计划时刻）+ 任务块列表（每块：标题 + 循环规则标签或"已错过"红色徽标 + 操作行）+ 底部收尾提示
- 操作行：【完成】（主按钮）+【5/10/30 分钟】分段组（来自设置 SnoozeMinutes）+【跳过】（弱化按钮）
- 浮入动画：TranslateY 16→0 + Opacity 0→1（0.3s ease-out）；**无花瓣动画、无声音**
- 收尾三动作沿用 3.3；全部条目收尾后窗口自动关闭（需求 3.4.2）；无关闭按钮、ESC/Alt+F4 屏蔽、未收尾 Closing 取消（需求 3.2.6）
- 提醒窗打开期间若睡眠 → 唤醒后窗口仍在，继续收尾（引擎豁免保护状态不乱）
- 多任务到期合并同一卡片逐条展示（需求 3.4.1）；主窗口行数据在卡片关闭后刷新

## 11 错误处理与轻量保障

- 全局兜底：`DispatcherUnhandledException` + `AppDomain.UnhandledException` → 日志 + HC 提示，进程内提醒机制不静默失效（需求 9.3）
- 轻量：仅 1s DispatcherTimer 轮询（纯内存比较）；无后台线程、无联网、无子进程；单实例内存目标 ≤100MB（需求 1.2.8）
