# QuietRemind 任务提醒工具 设计文档

> 依据 [需求.md](需求.md) 设计，本文档为开发基线：定义架构分层、领域模型、核心状态机、启动编排、模块契约、持久化格式与测试策略。

## 1 架构总览

| 层 | 目录 | 职责 | UI 依赖 |
| --- | --- | --- | --- |
| 领域模型 | `Models/` | Task / Occurrence / 枚举 / AppSettings | 无 |
| 服务层 | `Services/` | 实例规划、提醒引擎、错过扫描、关机拦截判定、计划任务守护、JSON 存储、日志、时钟、睡眠监听 | 无（可单元测试） |
| 视图模型 | `ViewModels/` | 主界面、编辑、收尾命令 | 仅基础类型 |
| 视图 | `Views/` | 主窗口 / 编辑窗 / 全屏提醒窗 / 关机拦截窗 | HandyControl |
| 基础设施 | `Helpers/` | RelayCommand、ViewModelBase、转换器、单实例 | 无 |
| 编排 | `App.xaml.cs` | 启动序列、全局异常兜底、系统事件挂接 | WPF |

**关键原则**：服务层零 UI 依赖——全部核心逻辑（生成、触发、错过、拦截判定、存储）不引用 WPF 类型，由 `IClock` 注入时间，可在测试工程中完整单测。UI 仅做展示与转发。

## 2 领域模型

### 2.2 Occurrence（任务实例）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| Id | Guid | 主键 |
| TaskId | Guid | 所属任务 |
| TriggerAt | DateTime | 当前计划触发时刻（snooze 时被更新） |
| OriginalTriggerAt | DateTime | 初始计划时刻（历史展示用，不可变） |
| State | enum | Pending / Missed / Completed / Skipped |
| ReminderShownAt | DateTime? | 本次进程内首次弹窗时刻（幂等标识，见 3.2） |
| PreAlertShownAt | DateTime? | 提前提醒（托盘气泡）已发出时刻（幂等；snooze 后不再补发） |
| SettledAt | DateTime? | 收尾时刻 |

**状态流转（终态不可逆）**：

```
              ┌───────────────────────────────────────────────┐
              │  snooze: TriggerAt=now+间隔, 回 Pending         │
              ▼                                               │
 Pending ──到点触发──► (弹窗, 状态不变, runtimeShown 标记) ──收尾──► Completed
    │                                                         └──────► Skipped
    └──错过扫描(启动/唤醒/轮询)──► Missed ──补提醒弹窗──► 收尾 ──► 终态
```

## 3 核心状态机（需求 3 / 5 章落地）

### 3.1 引擎内存态 `runtimeShown: HashSet<Guid>`

进程内"本次运行已弹过提醒"的实例集合。**仅存内存**，进程退出即清空——这是"强杀/关机后重启仍能补提醒"（需求 5.1.4）成立的机制基础。

### 3.2 四条判定规则（引擎每次轮询按序执行）

1. **触发判定**（需求 3.1）：`State==Pending && TriggerAt<=now && !runtimeShown.Contains(Id)` → 弹全屏提醒窗，`runtimeShown.Add`，`ReminderShownAt=now`（**不改 State**，收尾才改——需求 5.1.4）
2. **错过扫描**（需求 5.1，启动/唤醒/每轮询同一条规则）：`State==Pending && TriggerAt<=now && !runtimeShown.Contains(Id)` → `State=Missed`，补提醒弹窗（"已错过"徽标），`runtimeShown.Add`
3. **收尾**（需求 3.3）：【完成】→ `State=Completed`；【跳过】→ `State=Skipped`；【稍后再提醒】→ `TriggerAt=now+所选间隔`、`State=Pending`、`runtimeShown.Remove`、`ReminderShownAt=null`
4. **提前提醒**（需求 3.5，`PreAlertMinutes > 0` 才执行）：`Pending && PreAlertShownAt==null && TriggerAt==OriginalTriggerAt && now < TriggerAt <= now+N && !runtimeShown` → 设置 `PreAlertShownAt=now`，仅发托盘气泡；**不改变实例状态、不弹全屏窗**，snooze 偏离原计划后不预告

### 3.3 规则自洽性论证

| 场景 | 结果 |
| --- | --- |
| 到点正常触发后同轮询扫描 | 触发先执行并加入 runtimeShown → 扫描豁免，不误判"已错过"（5.1.2 第一条） |
| 提醒窗未收尾、进程被强杀 | runtimeShown 随进程消失 → 下次启动扫描：已过点未终态 → 判错过补提醒（5.1.4） |
| 时钟跳变整体跳过计划时刻 | 无 runtimeShown 保护 → 轮询兜底判错过补提醒（5.1.2 第二条） |
| 睡眠期间到点 | 唤醒扫描：未弹过 → 判错过补提醒 |
| snooze 推迟中关机 | TriggerAt 已更新为未来 → 关机拦截按"今天欠账"拦截；未拦到则下次开机扫描判错过（3.3 说明） |
| 提醒窗挂起期间轮询 | 已弹（runtimeShown）→ 豁免，状态不乱 |

## 4 模块设计

### 4.1 IClock / SystemClock / FakeClock

```csharp
public interface IClock { DateTime Now { get; } }
```

### 4.2 OccurrencePlanner（实例规划器）

- `EnsureUpTo(occurrences, tasks, horizonDays, notBefore)`：为每个**启用**任务补齐 `[max(生效起始日, notBefore), +7天)` 内缺失实例，返回新增数；按任务 Id 已存在实例去重；生效起始日 = StartDate 晚于今天时取 StartDate，否则取今天
- **日期回拨防护**：`notBefore` 通常传 `AppSettings.LastPlannedDate`（上次成功规划日期）。系统日期回拨 ≤7 天（与默认规划窗口一致）时跳过补生成，避免为已收尾历史日期重新生成实例；回拨幅度 >7 天视为时钟前跳残留，自动重置水位后继续规划，防止长期停止提醒
- 生成规则：Once 仅 SingleDate 一天（**不受 7 天窗口限制，设定即生成**，避免长期未运行后日期滑出窗口而静默丢失）；Daily 每天（每 N 天）；Weekly 勾选星期（每 N 周，以 StartDate 所在周为锚点）；Monthly 每月 MonthDay 日（`DateTime.DaysInMonth` 取月末，每 N 个月以 StartDate 所在月为锚点）；**Yearly 每年 Month 月 MonthDay 日，只生成下一次且不受 7 天窗口限制**（平年 2/29 取 2/28）；所有循环均受 EndDate（含当天）约束
- **间隔锚点**：Interval > 1 时编辑器强制要求 StartDate；脏数据缺少 StartDate 时按每 1 个周期处理（宁可多提醒，不静默漏提醒），DataSanitizer 记警告
- **当天已过时刻不追溯**（需求 2.3.1）：生成实例时 `at <= now` 跳过
- **编辑任务重建**：`RebuildFuture(ReminderTask)` 删除该任务全部未收尾实例（Pending/Missed，含已触发、已错过、snooze 推迟中的），按新规则重新生成并**立即生效**——编辑后当天按新时刻触发（需求 2.3.2，2026-09-19 用户澄清）；已收尾实例保留不动；去重时仅未收尾实例占位（同日已收尾不阻塞新实例生成）
- 停用任务：引擎过滤（不生成、不触发、不拦截），实例保留；**停用时未收尾实例统一置为 Skipped**（启动与启停切换时执行），避免重新启用时把停用前预生成的多日实例集中判为“已错过”
- **删除任务**：实例**全部保留**（需求 2.3.3"不清除已产生的历史实例记录"、8.3"保留供欠账判定"），引擎/拦截判定按"任务列表中不存在该任务"自然停止处理其全部实例
- Once 任务：最后一个实例收尾后任务转"已结束"（界面展示，`IsEnded` 计算属性：Once 且无 Pending/Missed 实例；主列表“下次提醒”列显示“已结束”）

### 4.3 ReminderEngine（提醒引擎）

- `Poll(occurrences, tasks, preAlertMinutes)`：每次轮询按序执行——常规轮询先**错过扫描**（cutoff=上次轮询时刻）再**触发判定**（窗口 `(上次轮询, 当前]`）；首轮 `_lastPoll` 初始化为 `now-2s`（启动扫描已处理过点实例，此处仅打开常规触发窗口）；**时钟跳变判定 = 墙钟间隔 >10s 且单调时钟（TickCount64）推进 <5s**，此时转全量错过扫描兜底；UI 卡顿/睡眠等单调时钟同步推进的大间隔仍走常规到点判定，避免把正常到点误标为“已错过”；`preAlertMinutes > 0` 时最后扫描提前提醒（0 时零工作）
- `ScanMissed(occurrences, tasks, now, cutoff)`：错过扫描（启动 / 睡眠唤醒 / 时钟跳变后显式调用），cutoff 之前到点且未弹过的 Pending 实例判错过并补提醒
- `ScanPreAlerts(occurrences, tasks, now, preAlertMinutes)`：启动/唤醒补扫提前提醒窗口，与轮询共用 `PreAlertShownAt` 幂等标记
- 触发与扫描均过滤停用任务实例（需求 2.3.4）；到期多条合并一次事件（需求 3.4）
- 收尾 `Settle(occurrence, action, interval?)`：完成/跳过终态；稍后再提醒推迟回待提醒（TriggerAt 偏离 OriginalTriggerAt，因此不再提前预告），实时落盘由调用方执行
- 秒级轮询：WPF `DispatcherTimer` 1s 间隔（轻量：仅做时间比较与内存集检查，无 IO、无高频空转）

### 4.4 ShutdownIntercept（关机拦截判定）

`GetOwedOccurrences(now, tasks, occurrences)` 欠账判定（需求 4.1）：

```
Task.Enabled && State==Pending && TriggerAt.Date == today
```

（Pending 且今天 → 无论时刻已过未过，关机后都提醒不到 → 拦截。明天任务不拦——"今天还欠着"。）

### 4.5 TaskSchedulerGuard（计划任务守护，需求 7 章）

基于 `Microsoft.Win32.TaskScheduler`（包 ID：`TaskScheduler`）：

- `EnsureRegistered()`：任务名 `QuietRemind`；**LogonTrigger 优先 + TimeTrigger 每 5 分钟重复**；`MultipleInstances.IgnoreNew`；`LogonType.InteractiveToken`（当前用户免密，需显式传 userId）；已存在且动作路径/参数、任务启用、登录触发器、守护触发器配置一致则幂等跳过；**注册使用 `CreateOrUpdate` 原地覆盖，不再先删除**（失败时旧任务保留）
- **降级机制**：部分环境（受限令牌）拒绝创建 LogonTrigger → 自动降级为**仅守护触发**并记日志；**登录/退出语义由当前进程令牌的登录会话 LUID（`TokenStatistics.AuthenticationId`）判定**：exit.marker 记录写入时的会话 LUID，与当前进程一致 → 本次登录会话内的守护触发静默退出；不一致或旧格式 → 清除标记并恢复提醒。同会话的手动/计划任务/提权进程 LUID 一致，注销重登、重启、快速启动重新登录后变化；不再依赖 TickCount64 或会话登录时间
- TimeTrigger 起点 = 注册时刻 + 5 分钟（避免固定次日起点造成注册当天近 24 小时守护空窗）
- `Unregister()`：注销任务（设置关闭时）
- `GetStatus()`：只读诊断（供设置区"运行状态"按需调用，不进入秒级轮询）——返回是否注册、任务启用、LogonTrigger/守护触发器是否存在、动作路径与 `--scheduled` 是否一致、上次运行时间/结果码及中文摘要（未注册/降级/配置不一致/一致）
- 返回操作结果（成功/失败原因）供界面提示

### 4.6 SingleInstance（单实例 + 唤醒）

- 命名 Mutex：优先 `Global\QuietRemind`（需求 1.2.7 全系统单实例），受限环境创建失败自动回退 `Local\`（会话级）
- 命名 EventWaitHandle `QuietRemind_ShowMain`（同样 Global 优先、Local 回退）：手动启动的重复实例 Set() 唤醒已有实例显示主窗口
- 已有实例**并入 1s 主轮询**消费信号（`TryConsumeShowMainSignal`，无常驻后台线程）

### 4.7 JsonStore（持久化）

- 目录 `%AppData%\QuietRemind\`，文件 `tasks.json` / `occurrences.json` / `settings.json`；**退出标记 `exit.marker` 存放于日志目录 `D:\logs\QuietRemind\`**——部分环境的计划任务守护进程对 `%AppData%` 新写入文件存在视图隔离，而日志目录在用户会话进程与守护进程间视图一致（实测验证）；D: 不可写时日志目录整体回退 `%AppData%\QuietRemind\logs`，标记/mutex.ns 同步使用回退目录
- System.Text.Json 序列化（枚举转字符串）；**原子写**：唯一临时文件（`.tmp` 带 Guid）→ `File.Move(overwrite)`（同目录改名即原子替换），断电/强杀不损坏
- 损坏恢复：解析失败 → 把原文件移动到 `.corrupt-时间戳` 备份 → 原路径重建为空数据并继续可写；**读取失败（瞬时占用/权限）→ 保留原文件，本次会话禁写该域，后续写入抛明确异常由上层提示**（不移动、不以空数据覆盖）
- 任何状态变更实时落盘（需求 8.2）：任务增删改、收尾、**错过判定**、标记写入与清除；`AppServices` 统一捕获落盘异常、写日志并通过托盘气泡提示

### 4.8 LogService（全局日志，需求 10 章）

- 路径 `D:\logs\QuietRemind\yyyy-MM-dd.log`（目录不存在自动创建；D: 不可写回退 `%AppData%\QuietRemind\logs`）
- 行格式：`[时间] [级别] 消息`；级别 Info / Warn / Error
- 全生命周期记录：启动/退出、守护拉起结果（含“已有主实例，跳过”）、任务增删改、实例状态流转、提醒触发、拦截交互结果、睡眠唤醒扫描、异常（含堆栈）
- 日志文件以 FileShare.ReadWrite 追加，允许守护/重复启动进程留痕；滚动清理：启动与每日首次写入时删除 30 天前文件（含 `startup-error-*.log`）；写失败静默（吞异常，不拖垮主流程）

### 4.9 SleepWatcher（睡眠唤醒）

`SystemEvents.PowerModeChanged`：`Suspend` 仅打 `_resumeScanRequired` 标记（不停止轮询，避免 Resume 事件丢失后程序永久停摆）；`Resume` 时在 UI 线程立即执行 `ScanMissed` + `ScanPreAlerts`，且轮询首轮检测到标记时先补做错过扫描/提前提醒再常规触发，避免定时器 tick 先于唤醒处理器把睡眠期间到点实例误当正常到点。

### 4.10 DataBackupService（数据备份，2026-11-24 追加）

- 备份包 `BackupBundle { Version=1, ExportedAt, Data }` 为单一 JSON（任务 + 实例 + 设置，枚举转字符串）
- `Export` 手动导出；`Import` 校验文件大小（≤50MB）、JSON 格式、版本与三个数据域，再用 DataSanitizer 归一化，错误以 `InvalidDataException` 中文消息返回
- `CreatePreImportBackup`：导入前写 `backups/backup-before-import-yyyyMMdd-HHmmss.json`，保留 10 份
- `TryCreateDailySnapshot`：启动时写 `snapshots/backup-yyyyMMdd.json`（同日不覆盖），保留 5 份
- 导入流程：校验 → 备份当前 → JsonStore 原子写三个文件 → 立即自动重启（新实例带 `--restart-after=<pid>`，等待旧进程退出后再抢单实例，避免互斥挡住）

### 4.11 GlobalHotkeyService（快速新增热键，2026-11-24 追加）

- 消息专用 HwndSource（`HWND_MESSAGE`）+ `RegisterHotKey(Ctrl+Alt+N)`；`Pressed` 事件在 UI 线程触发，事件驱动、无常驻线程
- `SetEnabled` 供设置开关即时注册/注销；注册失败（被占用）返回原因，记录日志并在运行状态卡展示，不改变提醒主流程

### 4.12 新增窗口（2026-11-24 追加）

- **HistoryWindow**：任务行"历史"入口，只读最近 200 条实例（计划时刻/状态/处理时间/推迟或补提醒说明），不写数据
- **QuickAddWindow**：Ctrl+Alt+N 呼出，内容 + 时刻 + 单次/每天，保存走现有 Planner/落盘/主界面刷新
- **ReminderWindow 预览模式**：合成一条不入库的实例，同一主屏全屏样式；隐藏收尾操作、可 ESC/关闭按钮关闭、不落盘；App 仍只对真实提醒保持"逐条收尾才能关闭"

### 4.13 主题系统（2026-11-25 追加）

- **设置**：`AppSettings.ThemeMode`（Light/Dark）+ `ThemeAccent`（配色标识），随 settings.json 落盘；旧数据缺字段时按浅色松绿启动，未知取值经 `ThemeAccentCatalog.Normalize` 回退，不阻断启动。
- **配色**：`ThemeAccentCatalog` 提供 6 套基准色（松绿/墨蓝/赭陶/紫檀/石墨/莓果）；`ThemePalette` 为纯函数，按 HSL 推导主色、悬停、软底与侧栏选中色，深色模式按色相提亮并按 WCAG 对比度自动决定主色上的文字用白或深墨。
- **应用**：`ThemeService.Apply` 把结果写入 `Application.Resources`（画刷 + Color 键），只更新与上次不同的键——同模式换主题色时约七成中性色不变；并按明暗切换 HandyControl 的 `SkinDefault`/`SkinDark`（仅模式变化时切换）。
- **为什么整键替换**：WPF 会冻结资源字典中的画刷，就地改 `Color` 对已加载界面无效；因此界面颜色统一用 `DynamicResource` 引用，配合整键替换实现不重启换肤。
- **验证**：`ThemePaletteTests` 对 6 色 × 2 模式逐一校验对比度闸门；离屏探针在真实窗口树中验证运行时不重启换肤，并渲染主窗/编辑窗/快速新增窗核对深色表现。

├─ 快速新增热键：按设置注册 Ctrl+Alt+N（失败仅记日志）

├─ 停用任务未收尾实例置 Skipped → 日期回拨检查（LastPlannedDate/notBefore）→ 实例补齐（EnsureUpTo）→ 全量落盘 → 错过扫描 → 提前提醒补扫

## 6 关机拦截交互（需求 4 章）

1. 系统发起关机/重启/注销 → WPF `Application.SessionEnding` 触发（UI 线程）
2. `GetOwedOccurrences` 为空 → 立即返回（静默放行，不设 Cancel）
3. 非空 → **在 SessionEnding 处理器内同步 `ShowDialog` 拦截窗**：模态消息泵运行期间，系统等待本进程回复 WM_QUERYENDSESSION，用户操作窗口不受影响
4. 拦截窗逐条列出任务内容与计划时刻（超长列表限高滚动，两个决策按钮始终可见），提供：
   - 【取消关机】→ `e.Cancel = true` → 系统撤销关机流程
   - 【仍要关机】→ 不设 Cancel → 系统按原始意图（关机/重启/注销）继续 → 实例保持 Pending 等待下次开机补提醒
   - 未显式选择时关闭窗口（X/Alt+F4）一律按【取消关机】处理，避免隐式放行
   - **ShowDialog 返回后立即写回 `e.Cancel`**；暂存提醒先展示成功再清空，展示异常保留并由轮询每 5 秒重试，避免异常吞掉用户已确认的取消
5. 拦截窗显示期间新到期的提醒先暂存，取消关机后再追加展示，避免 Topmost 全屏提醒覆盖关机决策
6. 无 ExitWindowsEx 重发 → 天然避免"重启 vs 关机无法区分"与"反复拦截"问题（需求 4.3.2）
7. 全程无声音；结果记日志

## 11 错误处理与轻量保障

- 全局兜底：`DispatcherUnhandledException` + `AppDomain.UnhandledException` → 日志 + HC 提示，进程内提醒机制不静默失效（需求 9.3）
- 落盘异常统一由 `AppServices` 捕获：提醒展示/收尾不因落盘失败中断；失败写日志并通过托盘气泡提示（30 秒节流）
- 轻量：仅 1s DispatcherTimer 轮询（纯内存比较）；快速新增热键为消息专用窗口事件驱动；运行诊断仅打开主界面/手动刷新时查询；历史记录按需只读最近 200 条；每日快照仅启动时写一次并保留 5 份；无后台线程、无联网、无子进程；单实例内存目标 ≤100MB（需求 1.2.8）；提醒背景图按 1920×1080 上限解码并限制上传 20MB；设置区预览用 640px 缩略图，拖动滑块只重算小图模糊
- 退出留痕：`OnExit` 记录 ExitCode；`%AppData%\QuietRemind\running.flag` 在正常退出时删除，下次启动若仍存在说明上次被强制结束或原生崩溃，便于区分“应用崩溃”与“外部终止”
- 主题切换：只写入发生变化的资源键（同模式换主题色时约七成键不变），避免连续切换产生大量资源通知
