# QuietRemind 代码评审记录

> 评审方式：code-review（max 级别）多视角并行审查 + 发布冒烟实测 + 问题复验。评审对象为基线提交 `1a22ea9` 及其后的修复。

## 一、评审流程

1. **多视角静态审查**：10 个独立视角（逐行扫描 / 移除行为审计 / 跨文件追踪 / 语言陷阱 / 包装正确性 / 复用 / 简化 / 效率 / 修复深度 / 规范符合性）对全部 25 个源文件审查；因 API 限流部分视角合并重跑
2. **发布冒烟实测**：Release 单文件构建后真实运行，逐项验证启动、计划任务注册、单实例、守护拉起、退出标记、内存占用
3. **修复复验**：每项修复后重新构建 + 单元测试 + 冒烟复验

## 二（续）、第二轮复审发现与处置

基线修复后，以"正确性综合"与"清理综合"两个合并视角对最新工作区再次复审，发现 18 项，全部处置如下。

### 正确性综合（10 项，全部 CONFIRMED 并修复）

| # | 发现 | 处置 |
| --- | --- | --- |
| C1 | **Missed 状态成黑洞**：错过实例落盘后进程死亡，重启后扫描只认 Pending、拦截判定也只认 Pending → 永远不再补提醒/拦截，直接违反 5.1.4/1.2.1 | 错过扫描与欠账判定条件放宽为 `Pending or Missed`；新增回归测试"已错过实例落盘后进程重启_再次扫描仍补提醒"、"今天已错过未收尾_拦截" |
| C2 | 唤醒错过扫描在 SystemEvents 后台线程执行引擎变更+落盘+建窗：与 UI 线程轮询并发写同一 JSON 临时文件、非线程创建 WPF 窗口、并发读写 _runtimeShown | OnPowerModeChanged 全部逻辑 `Dispatcher.Invoke` 封送回 UI 线程 |
| C3 | RebuildFuture 把"已弹窗、正在 snooze 等待再触发"的实例（Pending 且 ReminderShownAt=null）当未弹实例删除 → 推迟时刻丢失 | 删除条件增加 `TriggerAt == OriginalTriggerAt`（排除 snooze 推迟中的实例）；新增回归测试 |
| C4 | 任一数据文件损坏/瞬时读失败 → 整体空数据启动并无条件落盘 → 完好数据被清空 | JsonStore 重构：按域独立加载返回 LoadResult（Problems 列表）；损坏域本次会话禁写保留磁盘现场；IOException（瞬时锁）与损坏区分；新增 2 个回归测试 |
| C5 | OnStartup 异常被全局处理器 Handled → 无窗口无托盘僵尸进程，提醒机制静默死亡 | OnStartup 拆分 StartupCore + try/catch：启动失败写独立错误日志、弹窗提示、`Shutdown(-1)`；LogService 构造在 D:\logs 不可用时自动回退 `%AppData%\QuietRemind\logs` |
| C6 | Global→Local 回退按各进程令牌独立选择，可能双主（守护受限令牌用 Local、手动实例用 Global） | 引入命名空间协调文件 mutex.ns（日志目录，视图一致已验证）：主实例登记选择，后续实例按同命名空间探测；事件与互斥体命名空间绑定。混合令牌极端场景记为已知边界 |
| C7 | SameAction 不校验 LogonTrigger：一次降级后永久降级，环境恢复也不再重试；BuildDefinition 内 new TaskService 未释放 | SameAction 增加登录触发器存在性校验（降级任务不视为一致，每次启动重试完整配置）；BuildDefinition 改为复用调用方 TaskService |
| C8 | IsRecentBootStartup（uptime<2min）会把"开机 2 分钟内用户的退出决定"误判为登录语义清掉标记 | 登录语义改为"本次开机周期内第一次计划任务启动"：boot.marker 记录上次登记时刻，以系统启动时间为界；用户在实例运行后的退出始终由守护语义尊重；判定失败保守按登录语义（宁可多拉起） |
| C9 | 同一轮询内先发错过事件再发到期事件 → 弹两个全屏窗口，违反 3.4.1 | 引擎事件合并为单一 `RemindersDue(due, missed)`，一次 Poll 只发一次事件、一个窗口混排展示；新增回归测试 |
| C10 | 守护（--scheduled）拉起遇数据损坏也弹模态 MessageBox，阻塞启动序列违反 7.2.2 | 数据问题提示仅手动启动时弹窗；守护启动只落日志 |
