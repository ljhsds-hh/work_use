## 4. 评审发现事项

### 已修复（评审过程中当场处理）

1. HandyControl 3.5.1 的 XML 命名空间映射不含 `InfoElement`/`GrowlParent` 附加属性解析 → 改用显式 `clr-namespace` 引用；
2. `HandyControl.Controls.Window` 与 `System.Windows.Window` 类型歧义 → 移除多余 using；
3. `ValidateRootPath` 非法字符漏洞（.NET Core `GetFullPath` 不再校验）→ 增加逐段非法字符检查，补 2 个单测。

### 已知事项（评估后接受，记录在案）

| # | 事项 | 评估 |
| --- | --- | --- |
| 1 | 超长路径：根目录(≤240) + 工程名(≤64) 组合理论上可超 Windows MAX_PATH | 概率极低；命中时走"异常捕获→回滚→中文报错"兜底，不会闪退或留残缺目录；如需彻底支持可开启系统 LongPathsEnabled |
| 2 | 工程名去重按大小写不敏感处理 | 与 Windows NTFS 默认行为一致，属正确口径 |
| 3 | 批量上限 200、单名上限 64 字符为合理预设常量 | 均为 InputParser 公开常量，后续可调 |
| 4 | 未做自动化 UI 测试 | 单窗口工具型应用，以启动冒烟 + 单测覆盖核心逻辑，投入产出比最优 |
