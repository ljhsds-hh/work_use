## 3. 测试过程中发现并修复的缺陷

| # | 缺陷 | 级别 | 修复 |
| --- | --- | --- | --- |
| 1 | `ValidateRootPath` 未校验非法字符：.NET Core 起 `Path.GetFullPath` 不再检查 `< > * \|` 等字符，含非法字符的根目录会被放行 | 中 | 增加逐路径段非法字符显式检查（跳过盘符段） |

## 4.2 UI 终稿修正验证（2026-09-17 四次迭代，最终交付版）

针对用户提出的三项修正，逐项验证：

| # | 修正项 | 实现 | 验证证据 |
| --- | --- | --- | --- |
| 1 | 工程 Logo（窗口标题栏 + EXE 图标） | 程序化生成 7 档尺寸（16→256）多层图标 `Assets/app.ico`（翡翠→青渐变圆角块 + 层叠图形），csproj `ApplicationIcon` + 资源嵌入 | ✅ 截图确认标题栏与任务栏均显示新图标 |
| 2 | 编辑器行号：空输入时仅显示 `01`，随行数递增 | `MainViewModel.ComputeLineNumbers`（最小 1 行） | ✅ 空态截图仅 `01`；多行输入时行号随行数增长 |
| 3 | 骨架拓扑按文件夹层级**可折叠** | `TreeView` + 自绘 `TreeViewItem` 模板（18×18 折叠开关、文件夹/文件图标、Initialized 徽标）；`TreeNodeItem` 支持 `IsExpanded`，工程根默认展开 | ✅ UI Automation 读取 `ExpandCollapsePattern`：`Expanded → 点击箭头 → Collapsed → 再点击 → Expanded` |

**本轮修复的真实缺陷**（均由自动化验收暴露）：

| # | 缺陷 | 影响 | 修复 |
| --- | --- | --- | --- |
| 1 | `Icon="Assets/app.ico"` 相对 URI 被解析为 `views/assets/app.ico`（Window 位于 Views/ 目录） | 启动抛 `XamlParseException`，被全局兜底吞掉 → **程序无窗口运行**（严重） | 改为绝对 pack URI `pack://application:,,,/CreateTpl;component/Assets/app.ico` |
| 2 | 自绘 `TreeViewItem` 模板的 `ContentPresenter` 未绑定 `HeaderTemplate` | 拓扑树节点显示为类型名 `CreateTpl.Models.TreeNodeItem` | 补 `ContentTemplate="{TemplateBinding HeaderTemplate}"` |
| 3 | 折叠箭头用纯描边 `Path`（1.6px 命中区） | 点击箭头难以命中，折叠交互不可用 | 改为透明填充的 18×18 `ToggleButton`（含命中区）+ 展开态箭头旋转 |
| 4 | `TreeNodeItem` 未重写 `ToString()` | UI Automation/屏幕阅读器读出类型全名（无障碍缺陷） | 重写 `ToString() => Name` |

**验证方式**：单元测试 40 用例全通过；UI 自动化端到端（启动 → 填写 → 构建 → 结果/拓扑渲染 → 折叠交互 → 昼夜主题），脚本沉淀于 [UI自动化验收脚本.ps1](UI自动化验收脚本.ps1)。

**已知自动化限制（非产品缺陷）**：Windows 中文输入法环境下，脚本注入的 `Enter`（IME 在 TranslateMessage 阶段消费）、`Ctrl+V` 与 `WM_PASTE` 均无法写入 WPF 文本框（已用 UIA 焦点断言 + 剪贴板内容断言排除应用侧问题）。因此**多行批量输入**的 UI 路径改由单元测试保障（`InputParserTests` 覆盖分行/去重/校验全部分支），界面链路以单工程端到端验证；建议实际使用时通过粘贴多行清单体验批量能力。
