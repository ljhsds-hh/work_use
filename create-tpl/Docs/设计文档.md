# create-tpl 技术设计文档

> 版本：v1.0　|　日期：2026-09-17　|　关联文档：[需求.md](需求.md)

## 1. 设计概述

create-tpl 为 .NET 8 WPF 桌面工具，采用标准 MVVM 分层架构，UI 层全部基于 HandyControl 组件库。核心职责：接收用户输入的工程根目录与工程名称（支持批量多行），在根目录下按固定模板创建标准化工程目录结构，并对批量执行提供失败隔离与结果汇总。

## 2. 总体架构

```
┌─────────────────────────────────────────────┐
│  Views（WPF + HandyControl）                 │
│  MainWindow.xaml — 输入区 / 结果区 / 预览区   │
└──────────────┬──────────────────────────────┘
               │ Binding / Command
┌──────────────▼──────────────────────────────┐
│  ViewModels（MVVM 核心）                     │
│  MainViewModel — 参数、校验、命令、结果聚合    │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│  Services（业务逻辑，可单测）                 │
│  ProjectTemplateService — 模板创建引擎        │
│  InputParser — 批量名称解析/去重/校验          │
│  FolderPickerDialogService — 目录选择器隔离   │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│  文件系统（Directory / File API）             │
└─────────────────────────────────────────────┘
```

**分层原则**：
- View 只做界面呈现与绑定，不包含业务逻辑；
- ViewModel 编排流程（解析 → 校验 → 创建 → 汇总），通过 Command 驱动；
- Service 承载全部文件系统操作与规则判断，不依赖 WPF 类型，保证可单元测试；
- ViewModel 通过接口 `IFolderPickerService` 依赖目录选择器，便于测试与替换。

## 3. 模块设计

### 3.1 InputParser（输入解析与校验，纯函数，可单测）

| 规则 | 说明 |
| --- | --- |
| 分行解析 | 按换行拆分，Trim 首尾空格，忽略空行 |
| 去重 | 按首次出现顺序去重（忽略大小写，Windows 文件系统不区分大小写） |
| 非法字符校验 | 拒绝 `Path.GetInvalidFileNameChars()` 中的字符 |
| 保留名校验 | 拒绝 Windows 保留设备名（CON、PRN、AUX、NUL、COM1-9、LPT1-9，含带扩展名形式） |
| 特殊值校验 | 拒绝 `.`、`..`、以点/空格结尾的名称（Windows 目录名限制） |
| 长度校验 | 单个名称 ≤ 64 字符（预留深层路径余量），批量数量 ≤ 200（防止误粘贴超大批量） |

解析失败时返回明确的中文错误信息列表，由 ViewModel 整体提示、不开始生成。

### 3.2 ProjectTemplateService（模板创建引擎，可单测）

单个工程的创建流程（`CreateProjectAsync(root, name)`）：

1. 计算目标目录 `root/name`，已存在则返回 `Skipped`（提示"当前工程已存在，无需重复创建"）；
2. 创建 `Code/`、`Docs/` 目录；
3. 写入 `README.md`（空）、`Docs/需求.md`（空）、`CLAUDE.md`（固定文案）；
4. 任一步骤抛出异常 → **尽力回滚**已创建的工程文件夹（避免残留残缺工程），返回 `Failed` 及中文原因；
5. 成功返回 `Success` 及生成路径。

批量入口 `CreateBatchAsync(root, names, progress)`：

- 按输入顺序逐个创建；
- **单点失败隔离**：任一工程失败（Skipped/Failed）仅记录结果，不中断后续；
- 通过 `IProgress<T>` 上报每个工程的完成事件，UI 实时刷新；
- 最终返回全部结果列表，供汇总展示。

### 3.3 MainViewModel（流程编排）

- 命令：`CreateCommand`（生成）、`BrowseCommand`（选择根目录）、`ClearCommand`（清空重置）；
- 生成前：校验根目录（非法字符、盘符、绝对路径）、解析工程名列表，任一失败则 Growl 中文提示并终止；
- 根目录不存在时自动创建（含多级）；
- 生成中：`IsBusy = true`，禁用生成按钮，防止重复提交；
- 生成后：汇总 `成功 / 已存在跳过 / 失败` 三类计数；若有未完成工程，醒目列出**未完成清单及原因**；成功工程拼接目录树预览。

### 3.4 UI 设计（HandyControl 优先）

| 区域 | 控件 | 说明 |
| --- | --- | --- |
| 根目录输入 | `TextBox` + `Button`（浏览） | 浏览用 .NET 8 原生 `OpenFolderDialog`（HandyControl 无目录选择组件，属允许的原生兜底场景） |
| 工程名称输入 | 多行 `TextBox`（HandyControl 样式 + 水印） | 一行一个工程名 |
| 操作按钮 | HC `Button` Primary / Default | 生成模板、清空 |
| 结果汇总 | HC `Tag`/文本 + 三色统计 | 成功/跳过/失败计数 |
| 结果明细 | `ListBox` + 状态着色 | 每行：名称、状态、原因/路径 |
| 目录预览 | 只读等宽 `TextBox` | 成功工程的目录树文本 |
| 全局提示 | HC `Growl` | 校验错误、成功、失败汇总通知 |

## 4. 关键技术决策

| 决策点 | 结论 | 理由 |
| --- | --- | --- |
| 目标框架 | `net8.0-windows`（固定） | 需求强制 .NET 8；开发机 SDK 为 10.x，可直接编译 net8.0 目标 |
| 目录选择器 | `Microsoft.Win32.OpenFolderDialog` | .NET 8 WPF 内置，零额外依赖；HandyControl 无该组件 |
| 批量执行方式 | 顺序逐个 + 单点隔离 | 工程数量少、IO 为主，并发收益小且增加失败排查复杂度 |
| 失败回滚 | 尽力删除残缺目录 | 避免留下半成品工程污染根目录；回滚失败则在原因中如实说明 |
| 字符编码 | UTF-8（无 BOM） | Markdown 通用编码，中文正常显示 |
| 测试框架 | xUnit | .NET 生态标准，服务层纯逻辑可完整覆盖 |

## 5. 异常与容错矩阵

| 场景 | 处理 | 用户感知 |
| --- | --- | --- |
| 根目录路径非法（非法字符/相对路径） | 校验拦截 | Growl 中文提示，不生成 |
| 根目录不存在 | 自动创建（含多级） | 成功创建后正常生成 |
| 根目录无写权限 | 异常捕获 | 中文报错，不闪退 |
| 工程名非法（字符/保留名/过长） | 校验拦截，整体不开始 | 列出全部非法行及原因 |
| 工程已存在 | 跳过 | 标记"已存在"，不中断批量 |
| 创建中途异常 | 回滚 + 记录失败原因 | 标记"失败"+原因，不中断批量 |
| 批量存在未完成项 | 汇总醒目列出 | 明确提醒未完成工程清单及原因 |
| 未知异常 | 全局 try/catch + 顶层异常日志 | 友好提示，程序不崩溃 |

## 7. 发布方式

单文件独立发布命令（详见 [发布部署指南.md](发布部署指南.md)）：

```bash
dotnet publish src/CreateTpl -c Release -r win-x64 `
  -p:PublishSingleFile=true -p:SelfContained=true `
  -p:IncludeNativeLibrariesForSelfExtract=true
```

产物为免安装单文件 EXE，任意 Windows x64 设备双击即可运行。
