## 1 背景与目标

提交代码走 PR 票;正式出荷由专门人员编译全环境 DLL;**local 出荷**(紧急出盒)由开发自己编译 DLL 交给需要的人,PR 票保留但不 merge。

本工具解决 local 出荷前的手工排查问题:给定提交履历,自动算出**这次出荷涉及的全部 DLL / XAP 名称**,每行一个输出,避免人工遗漏。

## 2 核心规则(判定口径)

### 2.1 提交范围

- 用户选择一个分支后,在提交列表中**点选一条,或按住 Shift/Ctrl 选择连续的多条**提交;
- 多条提交必须是**父提交链条上连续的**(每条提交的第一父提交必须是下一条所选提交),不连续时明确报错、不出结果;
- 改动文件集合 = 所选各提交**每一笔碰过的文件的并集**(逐条 `git diff-tree` 取并集;改动又改回的文件也计入)。

### 2.2 文件 → 工程归属

- 递归扫描仓库全部 `*.csproj`(跳过 bin/obj/.git/packages/.svn 目录);
- 按 csproj 的 `Compile` / `Page` / `Content` / `EmbeddedResource` / `Resource` / `None` / `ApplicationDefinition` / `SplashScreen` / `DesignData*` 条目(相对 csproj 所在目录解析为绝对路径)建立 文件 → 工程 映射;
- csproj 文件本身被改动视为影响该工程;
- 改动文件不属于任何工程(如 .sln、.config、README)时忽略,但在状态栏提示个数。

### 2.3 工程输出名

- 普通工程:`AssemblyName` + 扩展名;`OutputType=Library` → `.dll`,否则 → `.exe`;
- **Silverlight application 工程**(csproj 含 `SilverlightApplication=true` 或 `XapFilename` 属性):
  - 被改动时,**同时输出其自身 dll 和对应 .xap**(xap 名取 `XapFilename` 文件名,缺省 `AssemblyName.xap`);
- **xap 连带规则**:凡 silverlight application 工程沿 `ProjectReference` / `Reference` 引用链(含传递引用)包含的工程被改动,该 application 的 **.xap 一并输出**(界面标注"xap 内含受影响 dll");application 自身也被改动时不重复输出;
- 输出清单去重、按名称排序,每行一个,自动复制到剪贴板。

## 3 界面与交互

- 仓库目录:手输或浏览选择;exe 位于仓库内时启动自动识别;
- 分支:下拉列出本地分支与 remote 分支,默认选中当前分支;
- 提交列表:每条显示 短SHA + 标题 + 作者,最近 300 条;
- 右侧上框:受影响工程 → 输出 的明细(连带 xap 带标注);
- 右侧下框:最终输出清单(每行一个);
- 底部状态栏:提交范围、改动文件数、受影响工程数、连带 xap 数、未匹配文件数。

## 4 命令行模式

```
LocalShipList.exe <仓库路径> <最新SHA> [<更旧SHA> ...]
```

- SHA 按**新到旧**排列,必须为连续提交;
- 输出与图形界面一致(每行一个),供脚本调用与自动化测试。

## 5 约束与边界

1. 不执行任何编译、不修改仓库,只读仓库与调用 git 只读命令;
2. 工作区中已删除的工程无法归属其历史改动(落入未匹配提示);如需支持,再迭代"按历史版本 csproj 归属";
3. 中文提交信息按 UTF-8 读取;
4. 工具随仓库提交履历演进:新增判定需求时,先更新本文件,再改代码,并用 fake_repo / 开源 Silverlight 仓库回归。
